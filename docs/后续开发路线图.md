# ComfyBridge 后续开发路线图

> 基线：develop `259b48c`（2026-10-10）
> 适用对象：接手继续开发、准备正式发布或需要安排下一轮迭代的人
> 状态口径：本文件区分「已实现」「已实现但只有降级能力」「只有单测/离线验证」「明确未实现」，
> 不直接沿用旧文档里的完成度标记。

## 1. 当前结论

项目的功能主干已经贯通：本地 ComfyUI 请求拦截、路由决策、Modal 执行、进度中继、
输出回传、请求日志、成本估算、节点/工作流/设置同步、卷管理、打包分发、首次配置向导、
离线兼容矩阵和 Playwright 管理台 e2e 都有对应实现。

第一轮发布收口正在 `feature/license-and-release-docs` 完成。除 live 真机全绿、
安装文档实测和上传/删除等 P1 能力外，不再有未知的发布阻断项：

1. **真机发布验收已形成自动化骨架，仍待真实环境归档**：真实 Modal + 真实 ComfyUI 的
   live 冒烟集已落地，覆盖预检、文生图、图生图、中断、重连、无输出；发布前必须在真实
   两端跑绿并保存结果。
2. **若干规划能力目前是可用但降级的实现**：模型上传没有分块/续传/MD5，删除没有引用检查和
   软删除，节点依赖没有重建前预检，`object_info` 合并策略不可配置，任务进度主要靠轮询。
3. **发布与运维材料已补齐，仍待新机器实测**：安装、排障、兼容性文档和 MIT `LICENSE`
   已落地；首次安装到云端首图仍需在干净机器上按文档全流程验收。
4. **架构边界已经明确**：管理 API 已加非回环鉴权保护；SQLite 和大量进程内状态意味着
   单实例假设，Modal CLI 是关键单点，预算护栏是估算而非 Modal 侧硬上限。

## 2. 优先级定义

| 优先级 | 含义 | 处理原则 |
| --- | --- | --- |
| P0 | 不完成就不能对外宣称稳定发布 | 必须真实环境验收，判定标准可复现 |
| P1 | 不阻塞小范围自用，但直接影响完整性和体验 | 纳入下一轮功能迭代 |
| P2 | 扩大使用范围或长期运维前必须处理 | 与发布形态绑定，提前设计 |
| P3 | 工程健康与维护成本 | 随功能迭代分批偿还，不做一次性大重构 |

## 3. P0：发布阻断项

### P0-1 建立真实两端的 live 冒烟集

**当前状态**

- `backend/tests/live/` 已落地 9 个 `@pytest.mark.live` 用例与运行说明。
- `pyproject.toml` 已声明 `live` marker，测试分层位置已经留好。
- 历史真机验证散落在 `FIXLIST.md`；live 集把可重复的发布前检查固定为测试命令。
- 现有自动化 e2e 使用隔离配置和离线空态，不依赖真实 ComfyUI/Modal。

**要做什么**

在 `backend/tests/live/` 落地 `@pytest.mark.live` 冒烟集，至少覆盖：

1. 本地 ComfyUI 健康检查与 `/object_info` 可读。
2. Modal Runner 部署状态、代理鉴权凭证有效、通道可拉起。
3. 文本生成图：请求路由到 Modal，执行成功，输出文件回传到本地 `output_dir`。
4. 图生图：输入文件预上传、执行、输出回传。
5. 中断：云端任务运行中调用 `/interrupt`，终态收敛为中断而不是悬挂。
6. 断线重连：桥接器侧 WS 断开后，靠 `/history` 兜底拿到最终状态与输出。
7. 无输出工作流：合法结束且不误报成功，用于防止旧的“0 文件误报完成”回归。
8. 全链路留痕：请求日志能还原决策、时间线、输出和成本。

**代码入口**

用例必须在缺少真实环境变量或缺少凭证时明确 skip，而不是假通过。CI 默认不跑 live，
由人工在发布前触发并归档结果。

### P1-4 `object_info` 合并策略可配置

**当前状态**

- `/object_info` 会把云端专有模型追加到本地清单，策略是固定的“本地 + 云端追加”。

**实现建议**

- `union` 保持当前兼容行为；`local-first` 在 class_type 冲突时完全使用本地 schema。
- 增加冲突诊断日志或在节点页暴露冲突清单，避免前端渲染异常时无法定位。

**代码入口**

- `backend/app/proxy/object_info.py`
- `backend/app/core/config.py`
- `backend/app/api/v1/config.py`

**验收标准**

- 两端存在同名 class_type 且 schema 不同，切换策略能观察到不同合并结果。

### P1-5 用 SSE 或事件流替代 JobDrawer 轮询

**当前状态**

**代码入口**

- SSE 不可用时前端自动回退轮询，不出现空白抽屉。

## 5. P2：运维与规模化前必须处理

### P2-1 管理面鉴权与部署边界

与 P0-5 是同一主题。进入多用户、局域网或远程访问前，需要从「本机工具」升级为
「有明确认证边界的服务」：API token、Origin 校验、审计日志、可选反向代理部署说明。

### P2-2 单实例假设与 SQLite

**现状**

- 请求日志、成本、作业状态等大量依赖 SQLite 和进程内状态。
- 各同步作业注册表后端重启即清空，部署任务状态也只存在内存。

**要做什么**

- 发布文档明确写出单实例限制：同一配置目录、同一后端实例、单进程。
- 若需要多实例，评估 PostgreSQL/Redis 或把核心状态迁移到共享存储。
- 至少把作业状态的持久化接口抽象出来，避免未来迁移时重写每个业务模块。

### P2-3 Modal CLI 单点与凭证失效处理

**现状**

- 卷、应用、容器、账单操作都经 modal CLI 子进程。
- CLI 缺失、网络抖动或凭证失效会同时影响多个功能，且错误形态不完全统一。

**要做什么**

- 增加启动自检和全局状态页，明确显示 CLI 版本、登录状态、网络延迟和最近一次失败。
- 将 CLI 错误分类为「未安装」「未登录」「网络失败」「权限不足」「远端状态不确定」。
- 对可重试错误加统一退避策略，对不可重试错误给用户明确下一步。

### P2-4 预算护栏的边界说明

**现状**

- 预算是按 GPU 单价和请求墙钟时间估算，并在桥接器侧控制是否回落或拒绝。
- 它不是 Modal 账户级硬上限，无法阻止临时修改配置、绕过桥接器或 Modal 侧计费波动。

**要做什么**

- 在 README、设置页和告警文案中明确这是「本地护栏」。
- 文档给出与 Modal 侧预算/告警配合使用的建议。
- 成本对账页持续显示估算与账单的比例偏差，避免单价过期后失真。

### P2-5 提交前隐私确认

**现状**

- 规划中提出过提交前隐私确认弹窗，目前没有对应实现。
- 工作流、图快照、日志可能包含路径、提示词和模型名。

**要做什么**

- 首次切换到云端执行时显示一次数据边界说明。
- 明确哪些数据会离开本机：图快照、输入文件、必要元数据、日志。
- 提供「不再提示」开关，并让开关状态可撤销。

## 9. 不要误判为“未开发”的既有能力

为了避免重复造轮子，以下能力已经存在，后续开发应在其上扩展：

- 数据面拦截：`/prompt`、`/api/prompt`、`/object_info`、`/interrupt` 与 `/{path}` 透传。
- Modal 执行通道：后台执行、WS 中继、history 权威兜底、输出回传、代理鉴权。
- 路由链：固定规则加可配置规则的 CRUD、排序、干跑和 presence 缓存。
- 同步能力：节点差异/同步/镜像固化、工作流双向同步、设置键级推拉、版本 pin 对齐。
- 管理台：十个功能页、首次配置向导、成本报表、JobDrawer、日志 SSE。
- 测试基线：249 个后端用例（另有 9 个 live 用例默认 skip）、三版本兼容矩阵、
  离线管理台 Playwright e2e。
- 发布基础：wheel 打包、前端嵌入、安装态 `comfy-bridge` 启动命令。
