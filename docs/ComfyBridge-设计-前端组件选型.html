2 关键决策

2.1 UI 库：Ant Design 5（并明确不用 Tailwind）

  • 场景匹配：本项目是"密集表格 + 多抽屉 + 分区表单"的控制台，AntD 的 Table/Form/Drawer/Steps/Tabs 是精确命中；shadcn/ui 这类 headless 方案需要逐个自己拼装，工作量约 3 倍，单人项目不划算。
  • 为什么不用 Tailwind：AntD 组件 + design token 覆盖几乎全部样式需求；Tailwind 与 AntD 的预设类混用易冲突，剩余的布局缝隙用 CSS Modules 补齐即可。
  • 代价与接受度：包体积比轻量库大（按需加载后首屏约 +300KB 级），本地工具不在意；主题定制走 ConfigProvider theme.token（主色 #4f5be8、zh_CN、紧凑密度），不做深度视觉定制。
  • 版本：React 18 + antd 5.x（React 19 虽有兼容层，保守选稳定组合）。

2.2 状态分层：Query 管服务端，zustand 管实时与 UI

层内容实现
服务端状态列表/详情/健康/成本等一切 GET 数据TanStack Query：queryKey 按资源域（requests/nodes/jobs/cost）；SSE 事件到达 → invalidateQueries 对应域
实时状态SSE 连接态、运行中任务表、上传队列、后端健康快照zustand 三个 store：sseStore、runtimeStore、uploadStore；SSE 事件只带 ID+摘要，详情按需 GET
UI 偏好侧栏折叠、实时开关默认值、表格列宽zustand persist → localStorage

明确不引入 Redux：本应用没有复杂派生状态链，Redux 的样板代码只为"规范"买单，对单人项目是负资产。

2.3 数据请求：原生 fetch 薄封装 + EventSource

  • api/client.ts 约 60 行：统一前缀（VITE_API_BASE）、非 2xx 抛 ApiError（携带后端 error body）、JSON 编解码、超时 AbortSignal；multipart（模型上传）与流式（SSE）由各 hook 自行处理。
  • 不选 axios：拦截器/转换器能力用不上；fetch 原生支持流与 AbortController；少 30KB。
  • SSE 用原生 EventSource：浏览器自带断线自动重连；onerror 时把 sseStore 标灰并显示重连中，页面列表不依赖 SSE 也能手动刷新。

2.4 表格与表单

  • 日志列表：AntD Table 受控分页（默认 50 行/页）+ 筛选栏 + 实时开关；若切换"无限滚动"模式用 AntD 5.9+ 的 virtual 属性，不引入 TanStack Table。
  • 差异矩阵（DiffMatrix）：AntD Table + 自定义单元格（两端 ✓/✗ 图标、构建中 Badge），分组行用 rowSpan 或树形 children。
  • 条件构建器（RuleBuilder）：AntD Form + Form.List 动态行；node/model 选择器的选项来自差异缓存与卷清单接口，不引入树形级联组件（Select mode="multiple" 够用）。
  • 校验策略：前端只做 UX 级校验（必填/格式），业务校验真相在后端 pydantic——避免两套规则漂移。

2.5 可视化：ECharts + 自绘甘特

  • 成本趋势：echarts-for-react 按需引入（LineChart + Grid/Tooltip/Legend/DataZoom 模块），本地/云端双色堆叠。
  • 时间线甘特（六阶段）：纯 CSS——每阶段一个 div，宽度 = 时长占比，悬停 Tooltip 显毫秒；不为一个静态条形图引入 gantt 库。
  • 节点矩阵统计视图（M2，可选）：ECharts heatmap 或直接表格着色，实现时二选一。

2.6 上传：自研 useChunkedUploader

  • 模型上传要求分块 + 断点续传 + MD5 校验，antd Upload 的 action 模式无法满足——只用它的 Upload.Dragger 做拖拽/选择壳，上传逻辑全部自研：
  • 流程：File → spark-md5 分块抽样算 hash → POST /api/models/upload 逐块（带 offset/total/hash）→ 失败从记录的 offset 续传 → 完成后失效 models 查询。
  • AbortController 支持取消/暂停；zustand uploadStore 保存队列与 offset（页面切换不丢进度）。
  • 依赖：spark-md5（增量哈希）+ @types/spark-md5。

2.7 只读查看：JSON / YAML / 工作流图

  • M1：图快照与 YAML 预览用 <pre> + AntD Typography.Paragraph copyable——只读场景不需要编辑器。
  • P2：JSON 树换 @uiw/react-json-view；YAML 高亮可选 shiki（构建时渲染，无运行时开销）。
  • 工作流图渲染（P2）：@xyflow/react（React Flow）+ elkjs 自动布局，把图快照画成节点图；不采用 iframe 嵌入 ComfyUI 前端（依赖其内部全局状态，跨版本脆弱）。

axiosfetch 薄封装覆盖；axios 无增量价值

5.2 按需加载与体积守则

  • ECharts 走按需注册（echarts/core + 用到的 chart/component 模块），不 import * as echarts。
  • AntD 依赖 Vite 自动 tree-shaking，禁止 import * as antd；构建产物预算：首屏 JS ≤ 600KB gzip，超出用 rollup-plugin-visualizer 排查。
  • ECharts/React Flow 等重组件用 React.lazy 拆 chunk（仪表盘图表、日志图查看器）。

5.3 版本升级策略

  • 锁主版本（^ 范围内升级）；antd/ECharts 大版本升级当作独立小任务（跑 e2e + 视觉走查），不随手升。
  • React 保持 18，待 antd 官方宣告 19 一线支持且 e2e 全绿后再评估。
