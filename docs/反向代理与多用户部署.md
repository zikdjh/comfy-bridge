# 反向代理与多用户部署

ComfyBridge 默认是**本机单用户工具**：只监听 `127.0.0.1`，不配置管理令牌即可用。
一旦要放到局域网、内网服务器或公网入口后面，就进入「有认证边界的服务」模式，
这份文档说明边界、令牌、Origin 白名单、审计与反代配置。适用 P2-1。

## 1. 部署前必须知道的边界

- **管理面**：`/api/v1/*`（`/api/v1/health` 除外）与 `/bridge/*`，受管理令牌保护。
- **数据面**：ComfyUI 原生路径（`/prompt`、`/ws`、`/object_info`、`/view`、`/upload`
  等）由桥接器透传到本地 ComfyUI，**不受管理令牌拦截**。这层等于「出图与控制的
  完整权限」，暴露它就是暴露 ComfyUI 本身。
- **单实例假设**：SQLite 与进程内作业状态不跨实例共享；不要让两个 ComfyBridge
  进程共用一个配置目录（见路线图 P2-2）。

结论：对外只应暴露**一个入口**，把管理面与数据面放在同一个认证边界内（见下）。

### 单实例边界（P2-2）

当前版本按**单机单实例**设计，发布与运维必须满足以下三条：

1. **同一个后端实例**：同一时刻只有一个 ComfyBridge 进程读写该配置目录，
   不要用多进程 / 多副本同时挂同一 `CB_CONFIG_DIR` 或 `~/.comfybridge`。
2. **同一个配置目录**：请求日志、成本、进程状态、对齐历史、节点差异缓存、
   上传会话等都以该目录为家；共享目录不能替代分布式存储。
3. **单进程**：作业状态（同步、卷上传下载、卷移动、镜像部署、本机扫描）保存在
   进程内，后端重启即清空；重启时会把遗留的 queued/running 记录收尾为 cancelled。

需要横向扩展时，先把状态从「本地 SQLite + 进程内存」迁到共享存储：

- **请求日志 / 成本 / 审计**：可迁 PostgreSQL（或兼容 SQL 的托管库）；
  需要跨实例一致的作业控制时，再引入 Redis 做协调与通知。
- **作业状态**：已抽出统一接缝 `app/core/job_store.py`（`JobStore` 协议 +
  `InMemoryJobStore` 默认实现），`sync/jobs.py` 与 `modal_volume/jobs.py` 已接入。
  未来新增 Redis / PostgreSQL 实现即可替换，无需重写各业务模块。
- **事件流**：`app/events` 是进程内总线，多实例需要改用 Redis Pub/Sub 或
  消息队列，否则 SSE 只能看到本实例的作业进度。
- **文件类状态**：上传分块、图快照等仍落在配置目录 / `data/`，多实例需要共享
  文件系统（对象存储或网络卷）并处理并发写。

在没有完成上述迁移前，请用反代保持**单上游**（Nginx 只指向一个
`127.0.0.1:8189`），不要对 `/api/v1` 做多后端负载均衡。

## 2. 配置管理令牌

非回环监听时未配置令牌会**拒绝启动**（`comfy-bridge --host 0.0.0.0` 会以退出码 2 退出）。

```powershell
# 方式一：环境变量（临时）
$env:CB_MANAGEMENT_TOKEN = "<足够长的随机串>"
comfy-bridge --host 0.0.0.0 --port 8189

# 方式二：写入配置目录（持久，推荐给服务化部署）
Set-Content -Path "$HOME\.comfybridge\management_token" -Value "<足够长的随机串>" -NoNewline
```

令牌**不写入 `config.toml`**，也不经设置 API 回传，避免随配置导出泄漏。生成建议：

```powershell
# 生成 32 字节随机令牌
[Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Max 256 }))
```

客户端认证方式：

- 浏览器访问管理台：弹 **Basic** 认证框（用户名任意，密码填令牌）。
- 脚本 / CI：`Authorization: Bearer <令牌>`，或 `X-ComfyBridge-Token: <令牌>`。

## 3. Origin 校验（CSRF 防护）

配置令牌后，管理面对带 `Origin` 头的请求做同源校验：

- `Origin` 与请求访问的 Host 同源 → 放行（同一入口下的正常前端调用）。
- 无 `Origin` → 放行（脚本、同站导航），仍受令牌约束。
- 跨站 `Origin` → **403 拒绝**，避免恶意站点借用浏览器已缓存的 Basic 凭证。

用独立前端域名或反代后 Host 变化时，把可信来源加入白名单：

```powershell
$env:CB_ALLOWED_ORIGINS = "https://bridge.example.com,https://admin.example.com"
```

反代务必透传原始协议与主机，否则同源判定会失败：

```
proxy_set_header Host $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

## 4. 审计日志

配置令牌后默认开启审计：**写操作**与**所有被拒请求（401/403）**各记一条 JSONL，
成功的只读请求不记，避免页面静态资源刷屏。

```jsonl
{"ts_ms":1760000000000,"method":"POST","path":"/api/v1/config","status":200,"client":"10.0.0.5","origin":"https://bridge.example.com","auth":"bearer","reason":"ok"}
```

位置：`<配置目录>/audit.log`（默认 `~/.comfybridge/audit.log`），单文件超 5MB 轮转一份
`audit.log.1`。可用环境变量覆盖：

| 变量 | 作用 |
| --- | --- |
| `CB_AUDIT_LOG=1` / `0` | 强制开启 / 关闭；不设时跟随「是否配置了管理令牌」 |
| `CB_AUDIT_LOG_PATH=<路径>` | 指定审计文件位置 |

**审计不落 Authorization、token、请求体**，只记方法、路径、状态码、客户端 IP、Origin、
认证方式与结果原因。

## 5. 反向代理示例（Nginx）

把 `/bridge/`（管理台）与根路径（ComfyUI 数据面）都收在同一个 TLS 入口与认证之后：

```nginx
server {
    listen 443 ssl;
    server_name bridge.example.com;

    ssl_certificate     /etc/ssl/bridge.pem;
    ssl_certificate_key /etc/ssl/bridge.key;

    location / {
        proxy_pass http://127.0.0.1:8189;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;      # /ws 中继
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;                    # 长任务 / SSE 不被掐断
        proxy_buffering off;                         # SSE / 流式响应
    }
}
```

如果反代层已做统一登录（OAuth / SSO），可以同时保留桥接器令牌做纵深防御；两者不冲突。

## 6. 边界检查清单

- [ ] 只用回环地址时，不配置令牌也能用；确认没有误绑 `0.0.0.0`。
- [ ] 对外监听前已配置足够强的令牌（`CB_MANAGEMENT_TOKEN` 或 `management_token` 文件）。
- [ ] 反代透传 `Host` / `X-Forwarded-Proto` / `X-Forwarded-For`。
- [ ] 独立前端域名已加入 `CB_ALLOWED_ORIGINS`。
- [ ] 确认只有一个 ComfyBridge 实例使用该配置目录。
- [ ] 确认没有对 `/api/v1` 做多实例负载均衡（当前仅支持单实例）。
- [ ] 已确认数据面（ComfyUI 透传）也在认证边界内，不是裸露的第二入口。
- [ ] 需要时检查 `audit.log` 里的 401/403 记录。
