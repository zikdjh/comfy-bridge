3. 版本对齐

桥接器把本地 ComfyUI 版本视为权威：

  1. 管理台“节点 → 版本对齐”写入 modal-runner/lock/comfyui_version.txt。
  2. Runner 的 modal deploy 重建镜像，并尝试拉起容器。
  3. 成功则保留 pin；失败则回滚 pin；超时进入不确定态并要求人工核对。
  4. 每次结果追加到 ~/.comfybridge/version_align_history.jsonl 的 JSONL 历史。

查看入口是“节点 → 对齐历史”，也可以：

powershellGet-Content "$HOME\.comfybridge\version_align_history.jsonl" -Tail 20

历史记录中的结局：

结局含义处理
ok部署成功，pin 已更新继续验证或出图
已回滚部署失败，pin 已恢复查看错误，修节点依赖或网络后重试
超时远端状态不确定先 modal app list / modal app logs，再决定重试
无需变更本地版本与 pin 一致正常

3.1 真实结局演练记录（2026-10-10）

演练使用隔离的临时 Runner 副本（app_name=comfyui-p3-3-drill，临时数据卷）， 不触碰生产 Runner comfyui-l40s，也没有向仓库提交任何凭证或密钥。

结局真实现场构造观察结果验证结论
ok独立 app 执行真实 modal deploy，pin 为可构建版本约 12 秒完成部署，远端应用进入 deployed成功路径可稳定落地
rolled_back把 pin 改为不存在的 v0.0.0-p3-3-missing，触发真实镜像构建git clone 因远端分支不存在返回 128，部署失败；失败不覆盖上一成功版本构建失败能被识别，调用方应恢复旧 pin/旧文件
timeout对可构建 pin 发起真实 deploy，并在 2 秒后终止客户端进程客户端被终止，远端 app 仍保持上一次 deployed 状态；状态未同步超时属于不确定态，必须保留新 pin 并人工核对，不能自动回滚或立即重试

超时后的人工核对顺序：

powershellmodal app list
modal app logs <app_name>
modal image logs <image_id>

确认远端没有正在进行的构建后，再决定重新发起部署或恢复 pin。管理台“节点 → 对齐历史” 会记录 timeout 及其错误文案，便于后续追溯。

4. 升版 SOP

当本地 ComfyUI 升级，或上游发布需要纳入支持的版本时：

  1. 记录目标 tag 和 commit，确认 Runner 镜像能够构建。
  2. 复制最近的夹具目录，例如 backend/tests/compat/fixtures/comfyui/v0.38.2 到新版本目录。
  3. 逐项对照上游 server.py、execution.py、main.py 更新协议夹具，不修改桥接器代码来迁就夹具。
  4. 更新 backend/tests/compat/manifest.json 的版本号与源码 sha256 指纹。
  5. 运行完整测试：
powershellcd backend
.venv\Scripts\python.exe -m pytest tests/compat -q
.venv\Scripts\python.exe -m pytest -q
  1. 若失败，先定位是夹具陈旧还是桥接器实现真有协议漂移；修复后补测试，再更新 README/本文矩阵。
  2. 在真实环境至少跑一次：
powershell$env:CB_LIVE = "1"
$env:CB_LIVE_MODAL = "1"
$env:CB_LIVE_FIXTURE_JSON = "C:/path/to/txt2img-api.json"
.venv\Scripts\python.exe -m pytest -m live -q

5. 已知不支持或降级项

项目当前状态影响
object_info 合并策略local-first / union / local-only 可配置云端 schema 需在节点页显式刷新；未刷新时只保证模型名并集
模型上传8 MiB 分块、断点续传、块级 MD5、整文件 MD5 校验、重启后从磁盘恢复前端可暂停/继续/删除会话；已完成真实 Modal 卷 120 MB 断点续传验收（R2-05）
删除保护引用检查（请求历史/图快照/本地工作流）+ 软删除到 .trash/<UTC>/，默认保留 7 天被引用模型需显式确认；恢复拒绝覆盖同名目标；后台每小时清理过期回收站
删除恢复回收站列表、恢复、永久清理已落地已完成真实 Modal 卷验收（R2-06）
节点依赖预检重建前静态约束 + 本机 pip dry-run resolver；结果 5 分钟缓存本机无法代表目标镜像时标记 unavailable 并继续远端 deploy，最终仍由 deploy 失败回滚兜底
任务状态推送统一 SSE 事件流（job/node_sync/deploy/cost_alert，支持 Last-Event-ID 重放）轮询仅作 15s/30s 断线兜底；事件流历史窗口溢出时下发 resync
多实例仍为单实例假设；作业状态已有 JobStore 接缝SQLite 与默认 InMemoryJobStore 不能跨实例共享；多实例需先迁 Redis/PostgreSQL 与共享事件总线
预算护栏本地按单价和时间估算不是 Modal 账户硬限制
Modal CLI关键单点；控制面已 SDK 化，deploy/流式 run/container 仍保留 CLI写操作不会自动重试；跨进程仅保留最近一次失败，重启后状态清空
