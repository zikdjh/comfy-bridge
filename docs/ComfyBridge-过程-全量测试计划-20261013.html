1. 测试定位与入口条件

本计划用于发布前全量真机回归。默认目标是确认「SDK 迁移后的控制面 + 保留 CLI 运维面 + ComfyUI 出图数据面」同时可用。

执行时必须使用真实浏览器点击、真实本地 ComfyUI、真实 Modal 凭证；API 只用于取证据与辅助查询，不允许用 mock 代替真机结论。

1.2 入口条件

  • 当前分支为 feature/modal-sdk-migration，且本地代码门禁已通过。
  • Modal Python SDK 1.5.x 可导入，状态页自检通过；如应用未部署，允许 app_state=None，但部署后必须变为 deployed。
  • Modal 凭证、代理鉴权凭证、数据卷 comfyui-data 均可访问。
  • 已准备至少 1 个本地可执行工作流、1 个云端专有模型工作流、1 张图生图输入图。
  • 已准备 1 个大于 8 MiB 的上传测试文件，确保至少拆成 2 个分块。
  • 已确认测试预算上限，建议单轮云端消耗不超过 $1.50；超限立即停止 P1/P2 扩展项。

3. 执行顺序与断点

  1. 只读基线：跑代码门禁，启动服务，检查三端健康与状态页。
  2. 管理台点击：先做无破坏页面遍历，再做临时配置类操作。
  3. 本地生图：确认 ComfyUI 工作流加载与本地输出。
  4. 云端生图：完成文生图、图生图、隐私确认、回传、日志与成本。
  5. 同步与模型卷：工作流/节点/设置同步，再执行分块上传、下载、删除、恢复。
  6. 运维与专项：版本对齐、镜像重建、deploy、container list/stop、warmup、多账号。
  7. 异常与安全：离线、中断、无凭证、隐私拒绝、无效工作流、路径防护。
  8. 发布验收：wheel、嵌入资源、pipx 安装态。
每完成一个阶段，先登记结果再进入下一阶段。若出现 P0/P1 问题，立即停止后续高成本云端用例，避免把问题掩盖在大量测试之后。

5. ComfyUI 工作流加载与生图测试

生图入口：http://127.0.0.1:8189/。桥接器接管数据面，ComfyUI 界面地址保持不变。

5.1 工作流加载基础操作

  1. 在 ComfyUI 顶部打开 Workflow 菜单，点击 Open / Load（若 UI 版本不同，使用等价的“加载工作流”入口）。
  2. 选择 fulltest-local-YYYYMMDD.json 或现有 krea2 文生图工作流。
  3. 等待画布渲染完成，检查模型节点、CLIP、VAE、KSampler、SaveImage 均可见，没有红色缺失模型/节点错误。
  4. 修改正向提示词为 ComfyBridge full test local 001。
  5. 点击 Queue Prompt / Queue。

预期：队列出现任务，预览图生成，任务终态为完成；媒体库新增图片，日志显示后端为 local，云端成本不增加。

11. 证据登记与验收标准

11.1 证据要求

  • 每个 P0 用例必须有截图或请求编号；云端生图必须记录 prompt_id、终态、耗时、输出文件名。
  • 卷操作必须记录远端路径、本地路径、文件大小、hash/MD5。
  • 部署与容器操作必须记录应用名、容器 ID、开始/结束时间、最终状态。
  • 账单对照必须同时记录 SDK 输出与 CLI 输出，以及差值。
  • 失败用例必须包含复现步骤、页面提示、后端日志片段、时间戳。

等级标准

带问题通过仅 P3 文案/体验问题，且已有登记与后续修复计划
不通过任一 P0 失败；生图无法完成；云端状态误报；凭证/数据出现安全风险
