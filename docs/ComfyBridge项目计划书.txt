  1 项目概述
      项目名称ComfyBridge —— 本地 ComfyUI 与 Modal 云端 GPU 之间的桥接器
      一句话定义本地常驻服务：把本地 ComfyUI 的生成请求按策略转发到 Modal 云端 GPU 执行，并对两端节点/配置/工作流做同步管理、统一记录日志与成本
      技术栈FastAPI（含 ASGI 反代 + WebSocket 中继）+ React（管理控制台）+ Modal Python SDK（云端 Runner 与数据卷）
      项目性质个人工具型项目，单人开发，服务自己的日常出图工作流
      总体周期8 个工作周 + 1 周缓冲，建议 2026-09-28 启动，2026-11-27 前完成（缓冲至 12-04）
      总工作量约 40 人日
      配套文档技术设计见《ComfyUI-Modal桥接器项目规划》；参考资料见《ComfyUI 启动参数参考》《Modal 云平台与 SDK 参考》
    立项背景
      本地显卡无法胜任大模型/高分辨率/批量出图；Modal 提供按秒计费的 L40S～B200 GPU，无闲置成本。
      直接把 ComfyUI 搬上 Modal 后，本地前端习惯、工作流与素材被割裂；两端环境（节点、版本、路径）会持续漂移。
      已有一份可用的 Modal 部署脚本（comfyui_app.py），Runner 与数据卷基础已具备，缺的是中间的桥接层。
  2 目标与成功标准
    2.1 项目目标
      G1 无感切换：用户仍用熟悉的 ComfyUI 界面出图，单次生成可留在本地或送上云端，切换零学习成本。
      G2 环境一致：两端节点、ComfyUI 版本、设置、工作流可一键对齐，漂移可发现、可修复。
      G3 可控上云：云端每次执行可追溯（决策链路、时间线、输出、成本），费用有预算护栏。
      G4 模型不自动同步：模型仅存于本地与 Modal 数据卷两处，由用户通过管理界面对卷按需供给。
    2.2 量化成功标准（KPI）
       |  | 指标 | 目标值
         | 混合后端连续使用一个工作日，生成请求失败率（桥接层自身原因） | 0
         | 本地新装 3 个自定义节点 → 云端可用（同步 + 镜像重建完成） | ≤ 10 分钟
         | 请求日志可还原率（决策 + 时间线 + 输出 + 成本估算） | 100%
         | 月度预算护栏生效（超限自动回落本地并通知） | 有效触发 ≥ 1 次验证
         | 全新机器从安装桥接器到云端首图 | ≤ 30 分钟
         | 核心链路 e2e 通过率 | 100%（冒烟集全绿）
  3 项目范围
      ✓ 范围内
      ① 透明反代拦截与策略路由（manual / tag / 节点可用性 / 模型可用性 / 默认）② WebSocket 事件中继与历史合并 ③ 输入预上传、输出回传 ④ 节点差异对比与同步（镜像固化 + 卷试装双模式）⑤ 设置与工作流双向同步 ⑥ Modal 模型数据卷管理（浏览/上传/HF 导入/删除/用量）⑦ 请求日志、成本估算与预算护栏 ⑧ React 管理控制台 ⑨ 打包分发与文档
      ✗ 范围外
      模型文件自动双向同步；ComfyUI 前端/服务端源码改造；多租户与团队配额；训练托管；与 Modal 账单系统的对账结算；v1 期多远端后端（RunPod 等，列入 v2）

  9 质量管理
      分层测试：单元（路由求值/锁文件/合并/成本）→ 集成（mock 两端 ComfyUI 的全端点行为矩阵 + 同步冲突用例）→ live 联调冒烟（文生图/图生图/独占节点/中断/断网重连）→ e2e（Playwright）→ 兼容矩阵（远端 2 个版本）。
      代码门禁：ruff + mypy 通过、单测通过方可合并；主干保持可运行。
      设计红线：所有对 ComfyUI 协议的假设集中封装在兼容层（proxy 模块），禁止散落；prompt_id、二进制预览帧、status 广播三类场景必须有专项用例。
      安全基线：桥接器仅绑 127.0.0.1；Runner 端点必须带 Token 鉴权；日志中的图快照仅本地存储；预算护栏默认开启。

  11 变更与沟通机制
    11.1 变更管理
      需求/方案变更 → 记录影响（工期/范围/风险）→ 更新计划与 ADR → 版本号 +1。技术决策沿用规划文档中的 ADR 表追加。
      范围裁剪顺序（延期时从后往前砍）：M4-3 打包 → M2-3 卷试装模式 → M3-2 分块续传（降级为整文件上传）→ M4-4 兼容矩阵（保留核心链路冒烟）。P0 红线：M0–M1 桥接主链路与日志永不裁剪。

       |  | 机制 | 内容

    12.2 术语表
       |  | 术语 | 含义
         | Runner | 部署在 Modal 上的 ComfyUI 云函数（源自 comfyui_app.py 的 comfyui-l40s App）
         | 桥接器 / Bridge | 本地 :8189 常驻服务（FastAPI + React），本项目主体
         | 中继 | 桥接器内按 prompt_id 解复用的双段 WebSocket 网关
         | 数据卷 | Modal Volume comfyui-data，持久化模型/节点/用户数据/输入输出
         | 锁文件 | nodes.lock.yaml：远端自定义节点与版本（commit）的精确清单，镜像重建依据
         | 预校验 | 提交前用目标端 object_info 缓存复刻 validate_prompt，提前拦截缺节点/缺模型
         | 按需供给 | 用户确认后把本地模型上传到卷（或 HF 直下），区别于"自动同步模型"
