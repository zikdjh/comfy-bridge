# ComfyBridge 兼容性矩阵

本文记录当前锁定版本、支持边界和升级流程。矩阵的机器可读夹具位于
`backend/tests/compat/manifest.json`，回归入口是 `backend/tests/compat/test_compat_matrix.py`。

## 1. 当前锁定矩阵

| 项目 | 锁定值 | 说明 |
| --- | --- | --- |
| ComfyUI 参照版本 | `v0.37.2`、`v0.38.0`、`v0.38.2` | 三版 `execution.py` 同哈希；`server.py` 仅差资产导入守卫 |
| Runner 默认 pin | `v0.37.4` | `modal-runner/runner.py` 的固定默认；生产部署由版本对齐写入 pin |
| ComfyUI 仓库 | `comfyanonymous/ComfyUI` | 只通过 HTTP/WS API 交互，不复制或链接其代码 |
| Modal CLI / SDK | `modal>=0.70`（当前锁文件为 1.5.x 兼容线） | 作为子进程调用；代理环境需要 `python-socks` |
| Python | `>=3.11` | wheel 的 `requires-python` |
| 前端 | Node.js 22 + pnpm 12（CI） | 打包后前端嵌入 wheel，不要求用户安装 Node |

“锁定”指桥接器已对这些版本的 `/prompt`、WS 事件、`/history`、输出回传、
`/internal/logs/raw` 和 `/object_info` 顶层键集做逐项协议断言，而不是说只能连接这些版本。

## 2. 协议消费面

矩阵按以下 13 个面组织，每个锁定版本都要通过：

| 协议面 | 桥接器消费点 | 夹具 |
| --- | --- | --- |
| `/prompt` 成功应答 | `runner/client.post_prompt` | `prompt_ack.json` |
| `/prompt` 400 拒绝 | 提交拒绝上浮 | `prompt_reject_400.json` |
| WS 成功事件 | `runner/executor._ws_pump` | `ws_events_success.json` |
| WS 错误事件 | 终态与错误归一 | `ws_events_error.json` |
| WS 中断事件 | `/interrupt` 收敛 | `ws_events_interrupted.json` |
| `/history` 成功 | `get_history` + 输出四桶 | `history_success.json` |
| `/history` 错误 | 三态分类 | `history_error.json` |
| `/history` 中断 | 三态分类 | `history_interrupted.json` |
| 容器日志 | `/internal/logs/raw` 归一 | `logs_raw.json` |
| `/object_info` | diff 矩阵顶层 class_type | `object_info.json` |
| 本地 WS tap | 本地事件状态回传 | 复用 success/error 事件 |
| 双通道终态 | WS 快路径 + history 权威兜底 | 复用 history/WS 夹具 |
| 输出越界拒绝 | 只允许 ComfyUI 输出桶和安全子路径 | `history_success.json` |

当前测试命令：

```powershell
cd backend
.venv\Scripts\python.exe -m pytest tests/compat -q
```

该矩阵离线运行，不需要 Modal 或本地 ComfyUI；最后一条输出应包含 `40 passed`。

## 3. 版本对齐

桥接器把本地 ComfyUI 版本视为权威：

1. 管理台“节点 → 版本对齐”写入 `modal-runner/lock/comfyui_version.txt`。
2. Runner 的 `modal deploy` 重建镜像，并尝试拉起容器。
3. 成功则保留 pin；失败则回滚 pin；超时进入不确定态并要求人工核对。
4. 每次结果追加到 `~/.comfybridge/version_align_history.jsonl` 的 JSONL 历史。

查看入口是“节点 → 对齐历史”，也可以：

```powershell
Get-Content "$HOME\.comfybridge\version_align_history.jsonl" -Tail 20
```

历史记录中的结局：

| 结局 | 含义 | 处理 |
| --- | --- | --- |
| `ok` | 部署成功，pin 已更新 | 继续验证或出图 |
| `已回滚` | 部署失败，pin 已恢复 | 查看错误，修节点依赖或网络后重试 |
| `超时` | 远端状态不确定 | 先 `modal app list` / `modal app logs`，再决定重试 |
| `无需变更` | 本地版本与 pin 一致 | 正常 |

## 4. 升版 SOP

当本地 ComfyUI 升级，或上游发布需要纳入支持的版本时：

1. 记录目标 tag 和 commit，确认 Runner 镜像能够构建。
2. 复制最近的夹具目录，例如
   `backend/tests/compat/fixtures/comfyui/v0.38.2` 到新版本目录。
3. 逐项对照上游 `server.py`、`execution.py`、`main.py` 更新协议夹具，不修改桥接器代码来迁就夹具。
4. 更新 `backend/tests/compat/manifest.json` 的版本号与源码 sha256 指纹。
5. 运行完整测试：

```powershell
cd backend
.venv\Scripts\python.exe -m pytest tests/compat -q
.venv\Scripts\python.exe -m pytest -q
```

6. 若失败，先定位是夹具陈旧还是桥接器实现真有协议漂移；修复后补测试，再更新 README/本文矩阵。
7. 在真实环境至少跑一次：

```powershell
$env:CB_LIVE = "1"
$env:CB_LIVE_MODAL = "1"
$env:CB_LIVE_FIXTURE_JSON = "C:/path/to/txt2img-api.json"
.venv\Scripts\python.exe -m pytest -m live -q
```

## 5. 已知不支持或降级项

| 项目 | 当前状态 | 影响 |
| --- | --- | --- |
| `object_info` 合并策略 | 固定“本地 + 云端追加” | 同名 schema 冲突不能切换 `local-first` |
| 模型上传 | 整文件上传 | 大模型中断后需要重新上传，尚无分块/续传/MD5 |
| 删除 | 删除前没有跨工作流/日志引用保护 | 误删后依赖 Modal 备份或重新下载 |
| 删除恢复 | 无回收站 | 不支持本地界面恢复 |
| 节点依赖预检 | 没有重建前 `pip resolve` | 冲突通常到 deploy 阶段才暴露，失败会回滚 |
| 任务状态推送 | 仍以多路轮询为主 | 长任务 UI 实时性受轮询间隔限制 |
| 多实例 | 单实例假设 | SQLite 和进程内作业状态不能跨实例共享 |
| 预算护栏 | 本地按单价和时间估算 | 不是 Modal 账户硬限制 |
| Modal CLI | 关键单点 | CLI 缺失、网络或登录异常会同时影响多项功能 |

## 6. 兼容性记录模板

每次发布把以下信息追加到发布记录或本文末尾：

```text
日期：
ComfyBridge commit：
本地 ComfyUI 版本/commit：
Runner pin：
模态版本：
兼容矩阵命令与结果：
live 冒烟命令与结果：
已知偏差：
```

发布前至少要有一份最近的真实环境 live 记录，以及一份 `pytest -q` 和
`pytest tests/compat -q` 的全绿记录。
