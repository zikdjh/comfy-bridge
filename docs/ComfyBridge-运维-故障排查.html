ComfyBridge 故障排查

ComfyBridge 文档 · 生成于 2026-10-13

先收集以下三类信息，再按现象定位：

powershellcomfy-bridge --help
Invoke-RestMethod http://127.0.0.1:18189/api/v1/health | ConvertTo-Json -Depth 8
Get-Content "$HOME\.comfybridge\config.toml"

日志位置通常在 ~/.comfybridge/。不要在公开环境输出 token_secret、proxy_token_secret 或完整工作流中的私人路径。

1. 管理台打不开或 401

现象判断处理
http://127.0.0.1:18189/bridge/ 连接失败进程未启动或端口被占用先运行 comfy-bridge；必要时换 --port
浏览器弹出 Basic 认证已配置管理令牌用户名任意，密码填同一令牌；或脚本带 Authorization: Bearer <token>
/api/v1 返回 401非回环监听需要令牌设置 CB_MANAGEMENT_TOKEN 或写入 <配置目录>/management_token，重启
未配置令牌却拒绝启动--host 不是回环地址改回 127.0.0.1，或先配置管理令牌
/bridge 正常但数据面 502本地 ComfyUI 不可达检查 local.comfy_url 和本地 8188 服务

health 是唯一无需令牌的管理端点，适合容器或反向代理做就绪探测。

2. 本地 ComfyUI 未连接

现象：health.local.online=false，管理台右上角显示离线。

  1. 确认本地 ComfyUI 正在运行：
powershellInvoke-RestMethod http://127.0.0.1:8188/system_stats
  1. 核对 ~/.comfybridge/config.toml 的 [local] comfy_url。
  2. 若开了代理，确认 127.0.0.1 没有被错误转发到代理。
  3. 检查 comfy_root 是否指向包含 main.py 的仓库根，而不是 models 或用户数据目录。
  4. 修改配置后在“设置 → 本地”重新校验；必要时重启桥接器。

3. Modal CLI 缺失、未登录或凭证错误

现象：卷、部署、账单或 Runner 状态操作同时失败。

powershellmodal --version
modal token info
  • not found：执行 python -m pipx install modal。
  • 未登录：执行 modal token new，或在管理台填写 token_id / token_secret。
  • Token validation failed：重新粘贴凭证，去掉尾部空白；确认 ak- 与 as- 没有错位。
  • 代理鉴权 401：检查 proxy_token_id / proxy_token_secret，它们必须是独立的 wk- / ws- 凭证。
  • 网络超时：先运行 modal app list 判断是网络问题还是应用问题；必要时配置代理后重试。

4. Runner 部署失败或超时

  1. 运行 modal app list，确认 comfyui-l40s 是否存在。
  2. 查看最后一次部署日志：
powershellmodal app logs comfyui-l40s
  1. 检查 ~/.comfybridge/config.toml 的 web_url 是否仍是旧地址。
  2. 若变更了 volume 或 app_name，重新执行 modal deploy modal-runner/runner.py。
  3. 版本对齐或节点重建超时后，先确认远端状态，再重试；不要连续并发触发 deploy。

管理台“节点 → 对齐历史”会记录 ok、已回滚、超时 和错误详情，可作为判断起点。

已知历史缺陷（LV-02，已修）：中文 Windows 下 modal CLI 的 stdout 默认走 GBK，
成功路径打印 ✓/🔨/🎉 会触发编码错误并以非零码退出，导致**镜像其实已构建成功、
UI 却报“部署失败，已回滚 pin”**。当前版本已强制 CLI 走 UTF-8；若仍看到“刚部署完
就报失败”，先手工执行 modal deploy modal-runner/runner.py 看真实退出码，
并确认 PYTHONUTF8=1、PYTHONIOENCODING=utf-8 是否生效。

5. 云端请求挂起、中断或断线

现象处理
首次请求长时间等待冷启动属正常，允许数十秒到数分钟；必要时使用预热
进度不动但容器运行中查看 Modal 日志和网络；桥接器会通过 /history 兜底最终状态
中断后状态长时间不收敛桥接器会先收掉实时转发连接再发 /interrupt，随后用 /history 兜底；若超过 1 分钟仍不动，请看下方说明
断线重连丢失进度重新连接后会以 /history 和请求日志还原；不要重复提交同一任务
无输出工作流终态是合法结束，不应误报“成功有文件”；查看历史与日志确认输出桶为空

已知历史缺陷（LV-01，已修）：Modal web_server 在 WS 实时转发连接存活期间只处理该
连接，/history、/queue、/interrupt 都会排队读超时。旧版本因此出现**中断送不达、
请求一直挂到 3600s**。当前版本每 45 秒主动收一次转发连接做权威判定，并在中断前先收
连接。若在旧版本上遇到该现象，停掉实时连接（或重启桥接器）即可让 /history 立即返回
真实结局。

6. 输出没有回传

  1. 检查 output_dir 是否是本地 ComfyUI 的 output 目录。
  2. 在日志详情中确认请求最终后端是 modal，且出现输出回传阶段。
  3. 查看 Modal 容器日志，确认工作流实际执行成功且生成的输出路径非空。
  4. 检查本地输出目录写入权限，以及杀毒软件是否拦截了写入。
  5. 若 /history 已有结果但本地无文件，记录 prompt_id、时间和日志片段后提交问题。

7. 节点或模型不一致

  • 本地缺节点：在“节点”页对比差异，安装后重启本地 ComfyUI。
  • 云端缺节点：同步节点或重建镜像；重建失败会自动回滚。
  • 模型只在云端：路由页的云端模型规则应把请求送到 Modal；object_info 合并尚不支持切换策略。
  • 版本不一致：在“节点”页执行版本对齐，失败时查看“对齐历史”和 modal app logs。
  • 提交前被拦截：这是 bridge.preflight 的预期行为；查看返回的缺失节点/模型列表，改为供给或改走本地。

8. 数据卷操作慢或清单不刷新

Modal Volume 的清单和元数据有延迟，尤其刚上传或删除后。

  1. 刷新“数据卷”页，等待再次读取。
  2. 若远端动作仍在进行，查看任务抽屉或下载/移动任务状态。
  3. 确认没有另一个 modal volume 命令正在操作同名卷。
  4. 重要数据先保留远端备份，再执行批量移动或删除。

9. 预算护栏误触发

预算护栏是基于本地 GPU 单价、请求墙钟时间估算的软限制，可能与 Modal 账单存在偏差。

  1. 在“成本”页查看估算是何时超过月预算。
  2. 对比 reconciliation 页面的估算与 Modal 账单比值。
  3. 若 Modal 单价已调整，在设置中更新 GPU 单价。
  4. 需要继续执行时临时提高月预算，或把 on_budget_exceed 改为回落本地。
  5. 它不是 Modal 硬上限；账户侧仍要设置预算告警。

10. 打包或安装失败

powershellpython -m pipx install --force .\dist\comfy_bridge-0.1.0-py3-none-any.whl
comfy-bridge --help
  • No module named app：确认执行的是 comfy-bridge 命令，而不是在源码目录中直接运行 Python 文件。
  • 旧版本仍在：pipx list 查看是否安装了多个包，使用 pipx uninstall 后再安装。
  • 端口占用：用 Get-NetTCPConnection -LocalPort 18189 查找占用进程，或使用 --port 18195。桌面模式默认 18189，被占用时自动尝试 18190-18193；显式指定端口不自动回退。
  • 前端空白：确认安装的是带 app/static 的 wheel；开发态请先执行 pnpm build:embed。
  • 开发态前端启动报 'node' is not recognized：node.exe 不在 PATH（pnpm 能找到但它调不到 node）。在管理台「设置 → 本地」的 Node.js 环境卡片点「检测」确认状态，PATH 找不到时手动指定 node.exe 绝对路径保存（[local].node_path）；或把 Node 安装目录加入系统 PATH 后重开终端。

11. 提交问题所需信息

请提供：

  • ComfyBridge、ComfyUI、Modal CLI 的版本；
  • GET /api/v1/health 的脱敏结果；
  • 失败请求的 prompt_id、最终后端、请求状态和时间；
  • 管理台日志中的关键时间线，以及 Modal 端对应的错误日志；
  • 已执行的命令和复现步骤。

不要提交完整凭证、私有模型路径或包含个人信息的原始工作流。
