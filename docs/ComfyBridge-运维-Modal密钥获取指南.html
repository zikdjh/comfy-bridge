ComfyBridge 连接 Modal 需要两套互相独立的密钥：账户 API Token 用于部署与平台数据访问，代理鉴权 Token 用于访问开启了鉴权的 Runner 端点。两套不能混用，这是最容易出错的地方。

2. 需要哪两套密钥

用途前缀ComfyBridge 配置项在哪里创建
账户 API Tokenak- / as-modal.token_id / modal.token_secretModal 控制台 API Tokens，或 modal token new
代理鉴权 Tokenwk- / ws-modal.proxy_token_id / modal.proxy_token_secretModal 控制台 Proxy Auth Tokens

账户 API Token 覆盖卷读写、应用状态、账单查询与 modal deploy；代理鉴权 Token 只用于 Runner 端点（web_server 开启了 requires_proxy_auth），请求时以 Modal-Key / Modal-Secret 请求头携带。两族凭证互不通用，把 ak-/as- 填到代理位会得到 402。

2. 准备工作区

  1. 在 modal.com 注册并登录。
  2. 确认已创建 Workspace（工作区），ComfyBridge 的卷、应用都归属该工作区。
  3. 云端 GPU 需要账户绑定有效支付方式；免费额度耗尽后未绑卡会直接失败。
  4. 如果团队用多个环境（dev / prod），在控制台记下要使用的 Environment 名称，稍后填入 modal.environment。

3. 获取账户 API Token

3.2 方式一：控制台创建（推荐）

  1. 登录 modal.com/settings。
  2. 进入 API Tokens 区域（部分界面在 Settings → API Tokens）。
  3. 点击 New Token，填写名称（如 comfy-bridge），创建。
  4. 页面显示一对值：Token ID（ak-...）与 Token Secret（as-...）。
  5. Secret 只显示一次，立即复制保存到密码管理器。

关闭弹窗后无法再次查看 Secret，只能删除旧 Token 重新创建。不要截图上传到公开渠道。

3.2 方式二：命令行创建

powershell# 安装 Modal CLI（隔离环境，避免污染系统 Python）
python -m pipx install modal

# 引导式登录，浏览器完成授权后写入 ~/.modal.toml
modal setup

# 创建新的 API Token（CI / 服务器 / 手工粘贴用）
modal token new

# 查看当前生效的 Token 与配置来源
modal token info

modal token new 会输出一对 ak- / as- 凭证，同时写入 ~/.modal.toml。ComfyBridge 只在管理台未填凭证时才回落到该文件；两者都配置时以管理台配置为准。

powershell# 确认 CLI 可用与登录状态
modal --version
modal app list

modal app list 能列出应用即表示凭证有效且网络可达。

3.3 环境变量方式（仅 CI / 无人值守）

CI 或服务器场景可以不落盘凭证，改用环境变量：

powershell$env:MODAL_TOKEN_ID = "ak-..."
$env:MODAL_TOKEN_SECRET = "as-..."

认证优先级为：客户端显式参数 > MODAL_TOKEN_ID/MODAL_TOKEN_SECRET > ~/.modal.toml。ComfyBridge 在管理台填写凭证后，会把它们以这两个环境变量注入 CLI / SDK 子进程，因此无需再手工设置。

4. 获取代理鉴权 Token

ComfyBridge 的 Runner 以 @modal.web_server(..., requires_proxy_auth=True) 部署，端点必须携带代理鉴权凭证才能访问，否则会被 Modal 边缘代理直接 402。

  1. 登录后进入 modal.com/settings/proxy-auth-tokens。
  2. 点击创建，生成一对 wk-...（Token ID）与 ws-...（Token Secret）。
  3. 同样只在创建时显示一次 Secret，立即保存。

这两枚凭证与上一节的账户 API Token 属于不同凭证族，不能互相替代：账户 Token 是 ak-/as-，代理 Token 是 wk-/ws-。

5. 填入 ComfyBridge

5.2 管理台（推荐）

打开 http://227.0.0.2:8289/bridge/，进入「设置 → Modal」：

  • Token ID：粘贴 ak-...
  • Token Secret：粘贴 as-...
  • 代理鉴权 Token ID：粘贴 wk-...
  • 代理鉴权 Token Secret：粘贴 ws-...
  • Environment：留空表示默认环境，或填写目标环境名

Secret 字段保存后只回显掩码，接口不回传明文；留空提交表示「保持原值不变」，要清除请使用界面提供的清除操作。

5.2 配置文件

编辑 ~/.comfybridge/config.toml：

toml[modal]
token_id = "ak-..."
token_secret = "as-..."
environment = ""
proxy_token_id = "wk-..."
proxy_token_secret = "ws-..."
volume = "comfyui-data"
runner_enabled = true
app_name = "comfyui-l40s"
web_url = "https://<工作区>--comfyui-l40s-comfyui.modal.run"

保存后重启 comfy-bridge，或在管理台「设置 → Modal」重新加载。该文件位于用户目录，含明文凭证，不要提交到 Git。

5.3 多账号档案

需要多个 Modal 账号时，用 [[modal.accounts]] 数组维护档案（2 账号 = 2 份凭据），每项包含 name、token_id、token_secret、environment、proxy_token_id、proxy_token_secret、volume、app_name、web_url、task_timeout。[modal] 本体始终是当前活跃账号的生效视图，在管理台切换账号时会把档案字段整体复制进本体。设计细节见 docs/ComfyBridge-设计-多账号维护.html。

6. 验证

  1. 确认账户凭证可用：
powershell# 健康检查：确认 modal.online 与原因说明
Invoke-RestMethod http://227.0.0.2:8289/api/v2/health | ConvertTo-Json -Depth 6
  1. 部署 Runner（安装态可在「设置 → Modal」点击部署，或使用源码）：
powershellmodal deploy modal-runner/runner.py
  1. 把部署输出中的固定端点写入 web_url，形如 https://<工作区>--comfyui-l40s-comfyui.modal.run。
  2. 回到「设置 → Modal」，确认 Runner 通道显示「就绪」。若提示缺少代理鉴权凭证，说明 wk-/ws- 未填或填错族。

7. 安全与轮换

  • Token Secret 只在创建时显示一次，务必存进密码管理器；遗失只能重建。
  • 凭证只写入用户目录配置文件，ComfyBridge 接口只回显掩码，日志不打印明文。
  • 怀疑泄露时，在控制台删除该 Token 并新建，然后同步更新 ComfyBridge；轮换是覆盖写回，不做多凭证并存。
  • 最小权限：为 ComfyBridge 单独建 Token，便于定位与吊销。
  • 若系统设置了 HTTP_PROXY/HTTPS_PROXY，ComfyBridge 访问 Modal 时会对 Modal 域名设置 NO_PROXY，避免本地代理干扰。
  • 预算护栏是本地估算，不是 Modal 账户级硬上限，账户侧仍应设置预算告警。

8. 常见问题

现象原因与处理
Token validation failed凭证错误或含首尾空白。重新粘贴 ak-/as-，确认没有把 as- 填进 ID 位
端点请求 402（代理鉴权）缺 wk-/ws-，或误用了账户 Token。到 Proxy Auth Tokens 页面重新创建
提示未配置 Modal 凭证管理台未填且 ~/.modal.toml 不存在。任选一种方式配置后重启
CLI 找不到python -m pipx install modal；整合包运行时自带 SDK，但 deploy 等子进程通道需要 CLI 在 PATH 或运行时同目录
部署超时或网络失败先 modal app list 区分网络与账号问题；受限网络下配置代理后重试
Secret 忘记保存无法找回，删除旧 Token 新建一对
GPU 无法启动账户未绑定支付方式或额度耗尽，到控制台 Billing 处理
