1 项目概述

项目代号 ComfyBridge：一个部署在本地机器上的桥接服务。它将本地 ComfyUI 的生成请求按策略转发到 Modal 云端 GPU 执行（也可留在本地），并对两端的自定义节点、配置、工作流做同步管理，同时统一记录全部请求日志、估算云端成本。模型文件不做自动同步，仅通过桥接器管理 Modal 数据卷中的模型（浏览 / 上传 / 删除 / HF 导入）。

1.1 背景与目标

  • 本地显卡跑不动大模型 / 高分辨率批量出图，Modal 可按秒计费弹性使用 L40S～B200，但直接把工作流搬到云端后，本地前端、习惯与素材全部割裂。
  • 两端环境漂移严重：本地装了节点云端没有（或反之）、工作流两边各一份、模型路径不一致，人工维护成本高。
  • 目标：用户无感切换——仍用熟悉的 ComfyUI 前端出图，由桥接器决定在哪跑；节点/配置/工作流一键对齐；云端执行全留痕、可估算成本。

范围界定

✓ 范围内
请求拦截与策略路由；WebSocket 事件中继；输入文件预上传与输出回传；节点差异对比与安装同步；配置与工作流双向同步；Modal 模型数据卷管理；请求日志与成本估算；管理控制台（React）
✗ 范围外
模型文件自动同步（明确不做）；本地 ComfyUI / ComfyUI-Manager 本体的功能改造；Modal 侧多租户；模型训练托管；计费结算系统（仅做估算与告警）

1.2 关键决策记录（ADR 摘要）

决策点选择理由 / 备选方案
拦截方式透明反向代理：桥接器监听 :8189，前端指向桥接器，桥接器按端点拦截转发到本地 :8188 或 Modal不改 ComfyUI 前端与服务器源码、升级无感。备选：改前端 API 层（侵入大）；双前端切换（体验割裂）
远程执行的 ComfyUI在 Modal 容器内跑原版 ComfyUI（web_server 暴露 8188），桥接器通过其 HTTP/WS API 交互节点生态零适配成本。备选：Headless 拆图执行（工作量大，兼容性差）
prompt_id 归属由桥接器生成 prompt_id 并写入提交载荷，两段 WS 事件 ID 天然对齐简化事件中继与日志关联；需在兼容性清单中验证目标版本支持客户端指定 prompt_id
节点安装模式双模式：镜像固化（锁文件进 Image，生产默认）+ 节点卷（Volume 挂载 custom_nodes，快速试装）镜像固化冷启动快、可回滚；卷模式免重建、试错成本低
存储SQLite（WAL）单文件库本地单机场景，零运维；日志大对象（工作流图 JSON）落文件目录、库内只存引用
Modal 调用方式桥接器进程内 import modal 使用 Python SDK（部署 Runner、操作 Volume）比 shell 调 CLI 可控、可拿到结构化结果；CLI 仅作兜底
版本对齐同步节点时校验并锁定远端 ComfyUI 版本 = 本地版本，前端版本一致避免 object_info / 前端协议不匹配导致渲染或提交失败
Modal 调用方式（实现修订 2026-09-27）卷/文件/应用探测统一走 modal CLI 子进程（app/modal_volume/client：注入凭证 env、超时兜底、--json 结构化解析）；SDK 仅在 modal-runner 侧使用，桥接器进程不 import modal凭证不进桥接器进程与代码库、CLI --json 输出已满足结构化需要；备选：进程内 SDK（原 ADR，暂未采用，Runner 部署需结构化结果时再引入）
设置键级推拉（M2-5 落地）GET/POST /api/v1/settings-sync(/apply)：按键 directions 单请求批量执行；本地 comfy.settings.json 原子替换写入 + modal volume get/put 直读写数据卷，不要求云端容器在运行；凭证类键（token/key/secret/password）回显掩码、推拉用真实值原设计 diff + push|pull 双接口；单端点批量避免两次调用间两端漂移，逐键方向已含 push/pull 语义。备选：按原设计拆双接口
节点清单与卷同步（M2-1/3 落地）本地扫描 custom_nodes/（git remote+commit、requirements.txt、启停状态、单文件节点）；云端以数据卷 custom_nodes/.comfybridge-manifest.json 为权威清单，同步/移除时维护，读取经 modal volume get，不要求容器运行；停用节点整目录按实际名落卷（目录名自带 .disabled 后缀，ComfyUI 加载与依赖安装均跳过）原设计 nodes.lock.yaml 服务于镜像固化，卷模式不依赖镜像重建即可即时试装；manifest 与节点文件同卷演进、schema 版本化，后续镜像固化可复用为锁文件来源。备选：仅靠 volume ls（拿不到 repo/commit/启用状态，已弃）
节点镜像固化（M2-2 落地 2026-09-30）本地扫描为权威渲染 nodes.lock.yaml（JSON 文本，YAML 1.2 子集）+ install_nodes.sh，镜像构建时 add_local_file 执行把启用节点依赖预装进镜像 → modal deploy 重建；失败自动回滚锁文件与上一版 Tag；与版本对齐共用单飞 deploy 通道，后端主进程不 import modal冷启动免逐节点 pip 安装。备选：仅卷模式（已保留为兜底：覆盖卷上新装/未固化节点）
Runner 端点鉴权（P0 安全落地 2026-09-30）runner web_server 开启 requires_proxy_auth；桥接侧 HTTP/WS 统一注入 Modal-Key/Secret 代理凭证（凭证只存 ~/.comfybridge/config.toml 或环境变量，API 响应掩码）云端出图端点不鉴权等于公网裸奔。备选：无鉴权 + 仅靠 URL 隐匿（不可接受）
路由规则链数据化（M3-1/2 落地 2026-09-30）固定链 manual → tag → cloud_model → default；自定义规则链存 [bridge.rules]（workflow_tag / gen_type / min_pixels / node_missing_local / node_missing_cloud），路由页 CRUD 排序，非空时插在 cloud_model 与 default 之间并替换内置 gen_type/size 两步；node_presence 依赖节点 class 两端在场缓存（持久化 + TTL 单飞 + 强制刷新端点）；决策全程留痕 rule_trace规则顺序与阈值随工作负载调优，不应改代码。备选：硬编码规则顺序（原设计）
成本记账口径（M4-1 落地 2026-09-30，报表 v2 2026-10-01）单价 × 请求墙钟秒数（提交→终态，含冷启动等待）按次入账 requests 表；并发复用容器按请求直加 = 保守上限，scaledown 保活窗口不计入；聚合读取时 SQL 现算（工作流运行统计 2026-10-02 同口径落地），不设 cost_daily 表与夜间重算任务。报表 v2：工作流/主模型聚合 + CSV 导出 + 逐项对账（本地估算 vs modal billing report 明细 GPU 计量，UTC 月）原设计「含 scaledown_window 保活」无法归属到请求，修订为请求墙钟口径；夜间重算任务对单机 SQLite 属过度设计。备选：维持原设计（成本口径失真）

3 核心设计

3.1 请求拦截与路由策略引擎

拦截端点清单（兼容层核心）

端点处理方式
POST /prompt核心拦截点：解析 API 格式工作流图 → 规则判定 → 本地透传 / 走 Modal 通道；统一改写 prompt_id、client_id
WS /ws?clientId=桥接器同时接受浏览器 WS 与两后端 WS，按 prompt_id 将执行事件路由回对应浏览器会话；断线指数退避重连
GET /object_info*合并本地与远端节点定义（同名以本地为准）返回，前端可渲染两端全部节点
GET /history* / /queue本地数据 + 桥接器记录的远端运行记录合并视图（远端记录由桥接器合成等价 history 结构）
GET /view本地文件直接回源；modal/ 前缀文件从桥接器落盘目录返回（回传后本地即有）
POST /upload/image|mask本地保存；若该输入被远端工作流引用，执行前再预上传远端（按 文件名+尺寸 哈希去重）
POST /interrupt按运行记录转发到对应后端（本地 / 远端）
/api/settings、/user/*透传本地，同时供同步引擎读写（见 3.4）
其余端点原样流式透传本地 ComfyUI（含静态前端资源）

路由规则模型（按序求值，首条命中生效）

规则类型条件示例说明
manual提交时用户在 UI 下拉框选择最高优先级，存在于前端注入的元数据 / header
tag工作流文件名前缀 cloud: 或图内自定义节点 BridgeHint工作流自带路由意图
node_presence 已实现 2026-09-30，M3-2图中包含本地缺失的节点 → Modal；包含远端缺失的节点 → 本地节点 class 两端在场缓存：本地 object_info + 云端探测（TTL 单飞、持久化、强制刷新端点）；云端探测可能触发冷启动，故缓存保鲜而非实时

3.2 Modal 执行通道（Runner App）

Runner 是一个独立部署在 Modal 的 App，桥接器负责其声明、部署与调用：

# modal-runner/runner.py（示意）
runner_image = (
    modal.Image.debian_slim(python_version="3.11")
    .apt_install("git")
    .pip_install("torch==2.8.0", "--extra-index-url", "https://download.pytorch.org/whl/cu128")  # 按 GPU 代际选择
    .run_commands("git clone https://github.com/comfyanonymous/ComfyUI /comfyui && cd /comfyui && pip install -r requirements.txt")
    .run_commands("bash /build/install_nodes.sh")     # 由节点锁文件生成，见 3.3
)

models_vol = modal.Volume.from_name("comfy-models", create_if_missing=True)
user_vol   = modal.Volume.from_name("comfy-user",   create_if_missing=True)

@app.function(image=runner_image, gpu="L40S", timeout=3600, scaledown_window=120,
              volumes={"/comfyui/models": models_vol, "/comfyui/user": user_vol},
              secrets=[modal_proxy_secret])            # Modal-Key/Secret 端点鉴权
@modal.concurrent(max_inputs=8)
@modal.web_server(8188, startup_timeout=600)
def comfyui():
    subprocess.Popen("python main.py --listen 0.0.0.0 --port 8188 "
                     "--extra-model-paths-config /comfyui/extra_model_paths.yaml", shell=True)
  • extra_model_paths.yaml 由桥接器生成：把 Volume 分类目录映射为 ComfyUI 模型分类（checkpoints/loras/vae/controlnet/…），随镜像或启动脚本注入。
  • 冷启动策略：默认 min_containers=0 省钱；UI 提供「预热」按钮（调 min_containers=1 或直接 warmup 调用）；首次卷读取慢属预期，文档标注。
  • 安全：Runner 端点用 Modal 代理 Token（Modal-Key / Modal-Secret）鉴权，不暴露公网；桥接器持有 Token 转发。已落地 2026-09-30（P0） web_server requires_proxy_auth；桥接侧 HTTP/WS 统一注入，见 ADR。
  • 并发：@modal.concurrent 复用容器跑多次生成；scaledown_window 控制保活时长（计费敏感项）。

3.3 节点同步引擎

环节设计
节点清单采集 已实现 2026-09-28本地：扫描 custom_nodes/，目录型包取 git remote URL + HEAD commit、requirements.txt 与启停状态，单文件节点单独登记；云端以数据卷 custom_nodes/.comfybridge-manifest.json 为权威清单（同步/移除时维护），经 modal volume get 免容器读取。Manager API 兜底已完成 2026-10-02：在线且装有 ComfyUI-Manager 时抓 /customnode/getlist 增强目录扫描（非 git 包补 repo、git 包补注册表版本与展示名；离线/未装/格式不识别静默降级，纯增强不影响主清单）
能力差异对比 已实现 2026-09-28GET /api/v1/nodes/diff 按节点包/单文件求并集，逐行给出 same|changed|missing_cloud|missing_local（含 commit 与启用状态一致性）；deep=1 时额外拉云端 /object_info 做 class_type 级差异，由 UI 显式触发（会冷启动容器）。路由引擎所需的 class 两端在场缓存已由 node_presence 落地（M3-2，见 3.1）；diff 持久化缓存已完成 2026-10-02（矩阵 120s TTL + deep class_type 块长期落盘重启不丢，防重复冷启动计费；同步/移除后失效，force=1 强制现算，缓存时刻在差异矩阵 UI 标注）

3.5 模型数据卷管理（不做自动同步）

  • 浏览：按 ComfyUI 分类目录（checkpoints / loras / vae / controlnet / upscale_models / …）列出卷内模型：名称、大小、mtime、引用计数（被哪些工作流用到，由日志统计）。
  • 本地上传：桥接器流式接收 → 分块写临时目录 → volume.put_file / 分块上传函数；支持断点续传与 MD5 校验；大文件（>2GB）建议改用 HF 导入或 modal volume put 命令行。
  • HF 导入：提交 {repo_id, file, 分类}，桥接器在 Modal 起临时函数用 hf_hub_download 直接落到卷（数据中心带宽，不经本地）。
  • 删除 / 回收：删除前检查引用（近期日志中使用过则警告）；保留 N 天软删除。
  • 用量与预算：卷容量统计；路由引擎依赖本清单做 model_presence 判定。

3.6 日志与成本估算

  • 每次请求记录：决策链路（命中规则 + 理由）、两端耗时分解（排队 / 加载 / 执行 / 回传）、事件时间线（从 WS 事件聚合的节点级耗时）、错误堆栈、输出清单、工作流图快照（存文件、库存哈希）。
  • 成本估算 M4-1 已实现 2026-09-30，口径见 ADR：GPU 单价（配置项，设置页可改）× 请求墙钟秒数（提交→终态，含冷启动等待），按次入账 requests 表；按次/按日/按月聚合为读取时 SQL 现算，UI 展示今日/本月花费与近 30 天逐日曲线。另接入 Modal 账单实时查询（CLI billing summary 子进程 + 缓存：账户级本期计量/积分抵扣/实际计费，UTC 月）。
  • 预算护栏 均已实现：月度预算上限（超限按 on_budget_exceed 自动回落本地或拒绝，决策留痕 budget_guardrail + 控制台告警）、云端最大并发数（在途任务计数达上限按不可用动作回落/拒绝，2026-10-01）、单次运行超时上限（task_timeout）。
  • 报表 v2 已实现 2026-10-01：「成本报表」页按工作流/主模型聚合（主模型 = checkpoint/扩散模型引用，提交时落库、历史启动回填）、CSV 导出（逐条流水/聚合，utf-8-sig）、逐项账单对账（本地估算 vs billing report 明细的 GPU 资源计量，UTC 月 + UTC 日界逐日双列，比值持续偏离 1 提示校准单价）。
  • 实时性：日志事件经 SSE 推送控制台；日志保留期可配置（默认 90 天，自动清理大对象）。

9 风险与对策

风险等级对策
远端冷启动延迟（数十秒～分钟级，镜像 + 卷首读）高UI 明示状态与进度；预热按钮 / min_containers 策略；镜像层精简；路由规则可按「即时性要求」回流本地
ComfyUI API/前端协议快速演进（/prompt、history 结构、WS 事件）高兼容层集中隔离所有端点假设；版本锁定 + 对齐提示；兼容性矩阵已落地并随 backend-tests job 进 CI（tests/compat 夹具矩阵 2026-10-03，对 v0.37.2/v0.38.0/v0.38.2 逐版本跑协议断言）
节点依赖地狱（同一节点两端环境不同；节点间依赖冲突）高锁文件精确到 commit；镜像重建失败自动回滚；卷模式先行试装；依赖冲突检测在重建前预跑 pip resolve
Modal 计费失控（忘关 scaledown、预热常驻）中月度预算 + 双向告警（Modal Dashboard 预算告警 + 桥接器本地硬切回）；每次运行成本入日志；默认 min_containers=0
大文件上传慢（本地 → 卷，家庭带宽）中分块 + 断点续传 + MD5；主推 HF 导入（云端直下）；文档引导用 modal volume put 批量导入
WS 中断/浏览器休眠导致事件丢失中指数退避重连；以 /history 轮询兜底合成最终态；prompt_id 幂等去重
隐私（提示词/工作流/输入图上云）中路由确认弹窗（可按工作流记住）；block_network / 不上传未引用素材；日志图快照本地存储、脱敏选项
object_info 合并导致前端渲染异常（节点 schema 冲突）低同节点以本地为准；远端版本锁定与本地一致；合并策略可配置（union/local-first）

10 测试策略

  • 单元：路由规则求值、锁文件生成/解析、hash/合并逻辑、成本估算（pytest）。
  • 集成：mock 两端 ComfyUI（respx + Fake WS）覆盖拦截端点全部行为矩阵（透传/改写/合并/回源）；同步引擎对 fixture 目录树的双向同步与冲突用例。
  • 联调（打标 live）：真实 Modal + 真实本地 ComfyUI 的冒烟集：文生图、图生图（输入预上传）、带独占节点工作流、中断、断网重连。
  • e2e：Playwright 驱动浏览器走桥接器出图并断言回显与日志。
  • 兼容性矩阵：远端 ComfyUI 锁定 2 个版本组合跑核心链路，防止上游协议漂移破坏桥接。已实现 2026-10-03（backend/tests/compat：上游源码 sha256 指纹溯源夹具 × 13 协议面 × 3 版本，0.8s 离线跑完，负向验证漂移可捕获；升版 SOP：复制夹具目录 → 更新指纹 → 跑矩阵）。

11 未来扩展（v2 备选）

  • 多远端后端：RunPod / 自有 VLLM 服务器 / 多个 Modal workspace，路由引擎天然支持扩展 target。
  • 成本报表升级（已于 v1 提前落地 2026-10-01）：按工作流/模型维度聚合、导出 CSV、对接 Modal 账单（billing report 明细）对账——见 §3.6 报表 v2。
  • 队列与优先级：本地排队室，高优先级任务抢占远端并发额度。
  • 模型缓存预热：按使用频率自动把热模型固定进镜像（小模型）或提前拉到 GPU 本地盘。
  • 团队模式：多用户共用一个 Modal workspace，桥接器加简单鉴权与配额。
