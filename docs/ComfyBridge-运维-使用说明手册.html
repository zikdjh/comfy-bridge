ComfyBridge 是「本地 ComfyUI × Modal 云端 GPU」的桥接器：对 ComfyUI 界面透明，按路由策略把生成请求分流到本地或 Modal 云端执行，并统一管理两端节点、配置、工作流、数据卷与成本。本手册面向使用者，覆盖安装、配置、日常操作与排障入口。

1. 产品概览

1.1 核心能力

能力说明
请求分流拦截 /prompt 等生成请求，按规则转发本地或 Modal，出图地址不变
透明代理浏览器指向桥接端口即可正常使用 ComfyUI，无需改工作流
节点同步对比本地与云端自定义节点差异，支持同步与镜像重建
工作流 / 设置同步两端工作流与配置对齐（不同步模型文件）
数据卷管理模型、节点、输入输出、工作流持久化在 Modal 数据卷
成本记录记录每次请求的耗时与费用估算，支持账单对账
多账号档案1 账号 = 1 份凭据，可在管理台切换

1.2 端口约定

用途默认地址
本地 ComfyUI（数据面）http://127.0.0.1:8188
桥接器（数据面 + 管理面）http://127.0.0.1:18189（默认；桌面占用时自动尝试 18190-18193）
管理台 GUIhttp://127.0.0.1:18189/bridge/
管理 APIhttp://127.0.0.1:18189/api/v1/

把 ComfyUI 界面地址的 :8188 换成 :18189 即接入桥接器，其余用法不变。

2. 安装与启动

2.1 方式一：整合包（推荐，免安装）

整合包内置完整 Python 运行时与全部依赖，解压即用，无需安装 Python、Node.js 或 pip：

textComfyBridge-0.1.0/
├── comfy-bridge.exe      # 桌面应用入口
├── runtime/              # 内置 Python 运行时（含依赖、应用、GUI 产物）
├── docs/                 # 使用说明手册与 Modal 密钥获取指南
└── 使用说明.txt
  1. 解压到任意目录（建议路径不含空格与中文）。
  2. 双击 comfy-bridge.exe，直接打开 ComfyBridge 桌面窗口。
  3. 在桌面窗口中使用管理台；关闭窗口会停止随应用启动的内置服务。
powershell# 指定本机端口
.\comfy-bridge.exe --port 18195

# 自检整合包完整性（Python / 应用 / GUI 三项）
.\comfy-bridge.exe --doctor

# 查看版本
.\comfy-bridge.exe --version

# 兼容脚本与排障：命令行模式，不打开桌面窗口
.\comfy-bridge.exe --console --host 127.0.0.1 --port 18189

桌面模式仅支持本机 --host / --port；需要监听非回环地址时请使用 --console。桌面窗口使用系统 WebView2，Windows 10/11 通常已自带。

整合包不含 ComfyUI 本体，数据面仍需你已有的本地 ComfyUI 或 Modal 云端提供。彻底卸载只需删除解压目录；配置与数据保存在用户目录 ~/.comfybridge，与整合包目录无关。

整合包升级与回滚

  1. 先在「设置 → 检查更新」确认版本；退出 ComfyBridge，确认窗口关闭后内置服务也已停止。
  2. 把新整合包解压到新的空目录，不要直接覆盖正在运行的旧目录。程序文件按目录版本保留，用户数据继续共用 ~/.comfybridge。
  3. 首次启动新版本时，后端会在数据库 schema 初始化或迁移前自动创建版本迁移备份；备份失败会停止启动，避免在无保护状态下改库。旧版已有配置或用户数据但尚未记录版本状态时，也会按旧安装升级处理并先创建备份。
  4. 在「设置 → 数据安全 → 版本与升级」确认当前版本、升级时间与最近启动自检。自检通过后可继续使用，并保留上一版目录一段时间。

回滚边界：程序回滚通过重新打开上一版解压目录完成；用户数据回滚则需在「数据安全 → 版本迁移备份」下载对应备份，选择该文件并「校验并暂存恢复」，重启应用后生效。恢复前系统还会创建当前状态备份，因此回滚操作本身也可撤回。升级前备份只读取复制旧数据库，不会在备份阶段自动补表或执行 schema 迁移。备份含 Modal 凭证，只保存在可信位置并仅通过管理员认证下载。

启动自检失败时不要继续删除数据目录。先在「数据安全」查看失败项和错误建议：磁盘空间不足先清理空间；权限不足先关闭占用文件的程序；数据库损坏则从已验证备份恢复。若新版本仍无法通过自检，打开上一版解压目录，并用版本迁移备份恢复数据。

3. 首次配置

首次启动后，管理台会自动弹出配置向导，按「检测 → Modal 凭证 → 本地 ComfyUI → 云端 Runner → 完成」五步走完即可。

3.1 本地 ComfyUI

  1. 填写 ComfyUI 仓库根目录（含 main.py、nodes.py、comfy/），例如 D:\ComfyUI\ComfyUI；不确定可点「扫描本机」自动发现（扫描排除 C 盘）。
  2. 点「校验」确认目录完整。
  3. 填写输出目录（本地 output 目录），云端结果回传落在此处。

3.2 Modal 凭证

需要两套独立凭证：账户 API Token（ak-/as-）与代理鉴权 Token（wk-/ws-）。获取方式详见 docs/ComfyBridge-运维-Modal密钥获取指南.html。

3.3 部署云端 Runner

powershellmodal deploy modal-runner/runner.py

把输出的固定端点填入 web_url，形如 https://<工作区>--comfyui-l40s-comfyui.modal.run。安装态也可在「设置 → Modal」点击部署，使用 wheel 内自带的 Runner 副本。

3.4 配置文件方式

配置保存在 ~/.comfybridge/config.toml，可参考 backend/config.example.toml。只识别 [local] / [bridge] / [modal] 三节，未列出的键会被忽略。

5. 出图流程

  1. 启动本地 ComfyUI，确认 http://127.0.0.1:8188 可访问。
  2. 启动 ComfyBridge 桌面应用；需要打开 ComfyUI 数据面时，在浏览器访问 http://127.0.0.1:18189（即 ComfyUI 界面）。
  3. 正常搭建或加载工作流，提交生成。
  4. 请求按路由规则分流：命中云端规则的走 Modal，其余留本地。
  5. 在管理台「日志」页查看请求时间线（提交 / 执行 / 回传）与最终后端。
  6. 结果回传到本地输出目录的对应子目录，「媒体库」页可直接浏览。

首次云端执行会经历容器冷启动，通常数十秒到数分钟。首次验证建议用低分辨率、少步数的小工作流，避免不必要的费用。可在「仪表盘」用「预热」按钮提前拉起容器。

5.1 判定是否真的走了云端

在「日志」页打开请求详情，确认终态记录里的 final_backend 为 modal（而不是 local），并且输出回传阶段存在。

6. 路由与分流

请求最终走哪一端由规则链决定。内置规则按生成类型与分辨率判断；在「路由」页可维护自定义规则链（按序求值，非空时替换内置那两条）。

配置项作用取值
bridge.default_backend兜底后端local / modal
bridge.video_backend视频类输出节点请求的后端local / modal
bridge.large_side_pixels大分辨率上云阈值（图最大边像素），0 关闭整数
bridge.on_modal_unavailable云端不可用时的动作fallback_local / reject

「路由」页还可按标签、云端独有模型等条件分流。请求提交前会做预检，缺节点或缺模型会按预检策略拦截或自动供给。

7. 节点与模型

7.1 节点

  • 「节点」页展示本地与云端自定义节点的差异列表。
  • 可执行同步（把节点清单与依赖推到云端）或重建镜像。
  • 重建失败会自动回滚到上一个可用 pin；过程记录在「对齐历史」，状态含 ok / 已回滚 / 超时。
  • 版本不一致时执行「版本对齐」，可让云端 ComfyUI 版本与本地一致。

7.2 模型

  • 「模型」页列出两端模型，支持本地 ↔ 云端同步。
  • 大模型支持分块上传：断点续传 + 整文件 MD5 校验，只有与声明 MD5 一致才通过。
  • 模型删除有引用保护，会检查工作流引用并支持回收站。
  • object_info 合并策略（设置 → 桥接）决定本地与云端模型清单如何合并：local-first（默认）/ union / local-only。

7.3 常见异常的处理顺序

现象优先检查下一步
启动时提示端口被占用Get-NetTCPConnection -LocalPort 18189 查看占用进程关闭残留的 ComfyBridge/ComfyUI，或用 --port 指定空闲端口；显式端口不会自动回退
更新检查失败是否启用系统代理，代理是否能访问 GitHub检查 HTTP_PROXY/HTTPS_PROXY；更新检查会随系统代理，桥接器的代理开关不影响它
升级后启动自检失败「设置 → 数据安全 → 版本与升级」的错误项按磁盘/权限/数据库建议处理；无法通过时打开上一版目录，恢复版本迁移备份
恢复后没有变化是否仍在运行恢复前的进程完全退出并重新打开；恢复只在启动早期应用
提示另一个实例正在恢复是否同时启动了多个 ComfyBridge 目录或进程等待另一个实例完成；若超过 30 秒仍占用，关闭残留实例后再启动。不要删除 .restore.lock 或数据目录
卷同步任务因重启中断任务抽屉中的 interrupted 状态先核对云端文件是否存在，再显式重试；不要假设中断任务已写入
部署任务因重启中断任务状态为 interrupted，提示远端结果不确定先执行 modal app list 核对应用状态与部署时间，再查看部署和镜像日志；确认前不要重复部署，也不要回滚无法确认的远端变更
本机扫描因重启中断扫描状态为 interrupted按需点击「扫描本机」重新发起；系统不会在启动时自动扫描磁盘

8. 数据卷

模型、自定义节点、输入输出、工作流全部持久化在 Modal 数据卷（默认 comfyui-data，挂载到容器 /data）。

  • 「数据卷」页可浏览目录、上传、下载、移动与删除文件。
  • 批量操作（移动 / 下载）以任务形式执行，进度在任务抽屉查看。
  • Modal 卷的清单与元数据有延迟，刚上传或删除后可能需要刷新。
  • 重要数据先保留远端备份再执行批量删除。
  • 改动 volume 或 app_name 后需要重新 modal deploy。

9. 成本与预算

  • 「成本」页记录每次请求的 GPU 单价、耗时与费用估算，并与 Modal 账单对账。
  • 「设置 → 护栏与预算」可设月度预算与云端并发上限，超限时按策略回落本地或拒绝。
  • 预算护栏是本地估算的软限制，不是 Modal 账户级硬上限；账户侧仍需配置预算告警。
  • 若 Modal 单价调整，在设置中更新 GPU 单价以保持估算准确。

数据安全操作

管理台「设置 → 数据安全」可设置请求记录保留期（默认 90 天）、创建和下载备份，以及选择备份恢复。保留清理只删除已结束请求、已结束作业和失去引用的图快照，不删除模型、成片、配置或上传会话。

备份包含 config.toml（含 Modal 凭证）、请求数据库、图快照、上传会话元数据和审计日志，应存放在可信位置。恢复文件会先校验结构、文件哈希和 SQLite 完整性，再暂存到 ~/.comfybridge/restore-staging.zip；必须重启 ComfyBridge 才应用。恢复会整体替换请求历史、配置、图快照和上传会话元数据，应用前会额外生成一份当前状态备份。

恢复前自动备份失败时，新恢复文件不会进入待恢复队列。启动应用恢复时，图快照和上传元数据按整组切换，配置、审计日志与数据库依次原子替换；任一替换失败会尽力回滚已切换资源，原数据库还会保留为 bridge.sqlite3.pre-restore。若提示磁盘空间不足、目录权限不足或数据库损坏，请按提示清理空间、关闭占用文件的程序或从「数据安全」选择已验证备份恢复。

恢复暂存和启动应用共用 ~/.comfybridge/.restore.lock 操作系统文件锁。多个实例同时启动时，只有一个实例可以消费暂存恢复包；其他实例会等待并在拿锁后重新检查。等待超过 30 秒会拒绝继续启动，避免在数据文件切换过程中打开半恢复数据库。锁文件由程序维护，不要手动删除。

powershell# 创建备份并下载（需管理员令牌时附带 Authorization）
Invoke-RestMethod -Method Post http://127.0.0.1:18189/api/v1/maintenance/backup `
  -ContentType 'application/json' -Body '{"reason":"manual"}'
Invoke-WebRequest http://127.0.0.1:18189/api/v1/maintenance/backups/<name> `
  -OutFile .\ComfyBridge-backup.zip

# 恢复请求体为原始 zip；不是 multipart 表单
Invoke-WebRequest -Method Post http://127.0.0.1:18189/api/v1/maintenance/restore `
  -ContentType 'application/zip' -InFile .\ComfyBridge-backup.zip

恢复前请退出正在执行的任务，确认没有部署、卷上传、下载或移动任务。备份不会包含模型权重、生成成片或 ComfyUI 本体。

GET /api/v1/maintenance 的 release 字段只返回版本、安装时间、迁移历史、备份记录与启动自检摘要，不返回凭证。版本迁移备份自动出现在同一备份列表和版本历史中，恢复接口与手动备份完全相同。

powershell# 健康检查（示例）
Invoke-RestMethod http://127.0.0.1:18189/api/v1/health | ConvertTo-Json -Depth 6

12. 安全与数据边界

  • 默认只监听 127.0.0.1；非回环监听必须先配置 CB_MANAGEMENT_TOKEN 或 ~/.comfybridge/management_token，否则拒绝启动。
  • 配置令牌后，/api/v1（health 除外）与 /bridge 需认证；跨站 Origin 默认 403，可信域名经 CB_ALLOWED_ORIGINS 白名单；写操作与被拒请求落 audit.log。
  • 不要把桥接器直接暴露到公网；远程访问请用可信网络或反向代理并保留令牌。
  • 生成请求上云时，工作流图、输入文件与必要元数据会发送到 Modal；日志与输出默认保存在本机。
  • ~/.comfybridge/config.toml 含明文凭证，不要提交到 Git 或粘贴到公开 issue。
  • 敏感字段（token_secret / proxy_token_secret）接口只回显掩码，日志不打印明文。
