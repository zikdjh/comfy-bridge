1.1 强制规则（AGENTS.md）

  • 真实出图一律走 Modal 云端通道：提交时显式携带 x-bridge-backend: modal，不传 local，不依赖默认路由把请求留在本地。
  • 不为了跑通用例触发本地模型加载或本地推理；不为本地生图下载、安装或搬运模型权重。
  • 本轮默认不执行任何本地生图用例（旧计划 GEN-01..03、LIVE-03 按此规则退役，见 §7/§17 说明）。
  • 判定依据：每条生图请求终态记录里 final_backend 必须是 modal。

2. 环境准备与基线门禁

2.1 入口条件

  • 当前分支 feature/modal-sdk-migration；后端 backend/.venv 可用；前端构建产物存在（管理台挂在 /bridge）。
  • Modal Python SDK 1.5.x 可导入；状态页自检通过（应用未部署时允许 app_state=None）。
  • Modal 凭证、代理鉴权凭证、数据卷 comfyui-data 均可访问。
  • 已准备：1 个本地可执行工作流 JSON（API 格式）、1 张图生图输入图、1 个大于 8 MiB 的上传测试文件、1 个可直连的下载 URL。
  • 已确认云端预算上限（建议单轮 ≤ $1.50）；镜像重建、预热、云端生图等高成本用例按 §3 顺序执行，超限立即停止。
  • 本地 ComfyUI 已启动（http://127.0.0.1:8188）；桥接器已启动（http://127.0.0.1:8189）。

3. 执行顺序与断点

  1. 只读先行（无副作用）：§4.1 健康检查 → §4 其余全部 GET → §5 DP 只读项 → §6 页面只读点击。
  2. 低风险写操作：配置读写（先改后还原）、路由规则临时规则、工作流对比/推送单条、目录/移动/软删恢复。
  3. 任务型操作：分块上传、URL 下载、模型卷推拉、节点同步、设置同步。
  4. 高成本云端操作（预算门禁）：预热（API-88/OPS-01）、云端生图（§7）、版本对齐与镜像重建（API-33/35、NODE-05/06、UI-47/48）、容器停止。
  5. 破坏性/异常：§14 NEG 全部、彻底删除（VOL-09）、账号删除（API-08）、卷删除（API-74）。
  6. 打包与升级（PKG，可独立窗口执行）。
断点规则：任何 P0 失败即停，记录后修复复测再继续；P1/P2 失败可先跳过并汇总。每完成一个模块在执行记录页即时改状态，不要攒到最后补填。
