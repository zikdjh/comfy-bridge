ComfyBridge 安装与首次使用

ComfyBridge 文档 · 生成于 2026-10-13
1. 前置条件2. 安装 ComfyBridge3. 启动与确认4. 配置本地 ComfyUI5. 配置 Modal 与 Runner6. 首次出图7. 常见下一步8. 安全与数据边界

本文面向首次在新机器上安装 ComfyBridge 的用户，命令均以 Windows PowerShell 为准。 开发态运行见仓库根目录 README.md；本文只描述打包后的安装态。

1. 前置条件

项目要求
操作系统Windows 10/11 x64
Python3.11 或更高；只用 pipx 安装时无需全局开发依赖
本地 ComfyUI已能正常启动并可访问，默认 http://127.0.0.1:8188
Modal 账户已创建账户，可生成 API Token，并具备部署应用的权限
pipx推荐；也可用 python -m venv 加 pip 替代
Node.js（仅开发态）仅源码开发运行前端（dev.ps1 / pnpm dev）需要 Node ≥ 18 且 node.exe 在 PATH；wheel 安装态不需要。可在管理台「设置 → 本地」的 Node.js 环境卡片自动检测或手动指定路径

如果只需要先验证本地桥接，可暂不配置 Modal；要跑云端生成则必须完成第 4、5 节。

2. 安装 ComfyBridge

2.1 安装 pipx

powershellpython -m pip install --user pipx
python -m pipx ensurepath

关闭并重新打开 PowerShell，使 PATH 生效。

2.2 安装 wheel

从发布产物安装：

powershellpipx install "C:\path\to\comfy_bridge-0.1.0-py3-none-any.whl"

确认命令可用：

powershellcomfy-bridge --help

wheel 已内嵌管理台和 Modal Runner 副本，不需要另装 Node.js 或前端依赖。

2.3 升级

powershellpipx install --force "C:\path\to\comfy_bridge-<新版本>-py3-none-any.whl"

升级前可备份 ~/.comfybridge/；配置、数据库、缓存和版本对齐历史都保存在该目录。

2.4 卸载

powershellpipx uninstall comfy-bridge

卸载不会删除 ~/.comfybridge/。确认不再使用后再手动删除该目录；其中可能含有 Modal 凭证、请求日志和本地数据库。

3. 启动与确认

powershellcomfy-bridge

默认监听 http://127.0.0.1:18189，管理台地址为 http://127.0.0.1:18189/bridge/。数据面仍在根路径，原有 ComfyUI 地址只需从 :8188 改为 :18189。

首次启动会创建 ~/.comfybridge/config.toml。也可以先复制字段说明：

powershellNew-Item -ItemType Directory -Force "$HOME\.comfybridge" | Out-Null
Copy-Item "C:\path\to\source\backend\config.example.toml" "$HOME\.comfybridge\config.toml"

回环地址部署无需管理令牌。若确实要从局域网访问，必须先设置长随机令牌：

powershell$env:CB_MANAGEMENT_TOKEN = "<随机长令牌>"
comfy-bridge --host 0.0.0.0

不要直接把服务暴露到公网。局域网部署至少还要配合 Windows 防火墙和可信网络限制。

4. 配置本地 ComfyUI

4.1 向导方式

  1. 打开 http://127.0.0.1:18189/bridge/。
  2. 按首次配置向导依次执行“检测 → Modal 凭证 → 本地 ComfyUI → 云端 Runner → 完成”。
  3. 本地 ComfyUI 步骤填写仓库根目录，例如 D:\ComfyUI\ComfyUI，填写后执行校验。
  4. 输出目录填写本地 ComfyUI 的 output 目录，例如 D:\ComfyUI\output。

4.2 配置文件方式

编辑 ~/.comfybridge/config.toml：

toml[local]
comfy_url = "http://127.0.0.1:8188"
comfy_root = "D:/ComfyUI/ComfyUI"
output_dir = "D:/ComfyUI/output"

保存后在管理台“设置 → 本地”重新加载，或重启 comfy-bridge。comfy_root 必须包含 main.py、nodes.py 和 comfy/ 等必需目录；管理台校验会拒绝不完整目录。

4.3 验证

启动本地 ComfyUI 后访问：

powershellInvoke-RestMethod http://127.0.0.1:18189/api/v1/health | ConvertTo-Json -Depth 6

确认 local.online 为 true。若为 false，先检查 comfy_url 和本地服务端口。

5. 配置 Modal 与 Runner

5.1 安装并登录 Modal CLI

powershellpython -m pipx install modal
modal token new

也可以从 Modal 控制台生成 ak-... 与 as-... 凭证。

5.2 创建代理鉴权凭证

Runner 端点开启了 requires_proxy_auth。在 Modal 控制台的 Proxy Auth Tokens 页面 创建一对独立凭证：

  • wk-... 填入管理台“设置 → Modal → proxy_token_id”；
  • ws-... 填入 proxy_token_secret。

代理凭证与账户 API Token 不是同一套，不能混用。

5.3 在管理台填写凭证

进入“设置 → Modal”，填写：

  • token_id / token_secret：账户 API Token，用于部署、卷和账单操作；
  • proxy_token_id / proxy_token_secret：Runner 代理鉴权凭证；
  • volume：默认 comfyui-data；
  • app_name：默认 comfyui-l40s；
  • runner_enabled：保持开启。

保存后可先用“测试”或刷新状态确认 CLI 已登录且配置被后端读取。

5.4 部署 Runner

安装态应通过管理台执行部署：进入“设置 → Modal”，确认凭证保存后点击“部署 Runner”。 该入口调用 wheel 内自带的 Runner 副本，不需要另存源码。

只有开发态或需要手工排障时，才直接使用仓库源码：

powershellmodal deploy "C:\path\to\modal-runner\runner.py"

部署输出中的固定 Web URL 形如：

texthttps://<workspace>--comfyui-l40s-comfyui.modal.run

把该地址填入“设置 → Modal → web_url”。管理台“仪表盘”或“设置”页的 Runner 状态变为 就绪后，表示桥接器已经能拉起云端容器。

如果使用手工部署，Modal Runner 副本仍在 pipx 包内；管理台的节点同步、版本对齐和 数据卷任务都会调用包内副本，不需要额外维护第二份源码。

6. 首次出图

  1. 在本地 ComfyUI 中准备一个简单的文生图工作流，并确认本地能跑通。
  2. 先不强制上云，运行一次本地请求，确认本地节点和输出目录正常。
  3. 在管理台“路由”页创建或启用规则，让目标工作流走 modal；也可以暂时设置 bridge.default_backend = "modal"。
  4. 在 ComfyUI 界面提交工作流。
  5. 打开“日志”页，确认请求最终目标为 Modal、时间线出现提交/执行/回传，且输出进入历史画廊。
  6. 回到本地输出目录，确认云端结果已回传到 output\modal\ 等子目录。

第一次云端执行会经历冷启动，通常需要数十秒到数分钟。首次验证建议使用低分辨率、少步数的 小型工作流，避免在准备阶段产生不必要费用。

7. 常见下一步

  • 节点一致性：进入“节点”页查看两端差异，再决定同步或重建镜像。
  • 模型：进入“数据卷”页导入或下载模型；当前上传能力仍是整文件上传。
  • 预算：进入“设置 → 桥接”设置月度预算和云端并发上限。
  • 实时排查：日志页和设置页的本地/Modal 日志 SSE 可直接查看执行输出。
  • Node.js 环境（开发态）：进入“设置 → 本地”查看 Node.js 环境卡片，点击「检测」可自动按 手动指定路径 → PATH → 常见安装目录 顺序定位 node.exe 并回显版本；PATH 找不到时在卡片里手动指定路径保存（写入 ~/.comfybridge/config.toml 的 [local].node_path，保存即热生效）。wheel 安装态无需 Node。
  • 发布前验证：按 backend/tests/live/README.md 准备真实两端 live 冒烟。

8. 安全与数据边界

  • 默认只监听 127.0.0.1；非回环监听必须配置 CB_MANAGEMENT_TOKEN 或 ~/.comfybridge/management_token。
  • 不要在公网直接开放 18189。需要远程访问时使用可信网络或反向代理，并继续保留令牌。
  • 生成请求上云时，工作流图、输入文件和必要元数据会发送到 Modal；日志和输出默认保存在本机。
  • ~/.comfybridge/config.toml 含凭证，不要提交到 Git，也不要粘贴到公开 issue。
  • 预算护栏是本地估算和拦截，不是 Modal 账户级硬上限；账户侧仍应配置预算告警。
