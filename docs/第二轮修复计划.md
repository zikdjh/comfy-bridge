## 2. 本轮修复记录

### R2-01 透传 Origin 不改写导致 403（P1）

**发现路径**：多组提示词 Playwright 验证（`frontend/e2e/multi-submit-verify.spec.ts`）
全部走 `/prompt` + JSON 正常提交；图格式提交走 `_forward_raw` 兜底，此前盘点
（见《真机验收缺陷清单》§5 观察项之外）发现该路径未复用 `forward_request`
的 Origin/Referer 改写逻辑。

**根因**：`prompt_submit._forward_raw` 自拼转发头，只剥离了 host/content-length/
connection 等逐跳头，没有把 `Origin: http://127.0.0.1:8189` 改写为上游地址。
ComfyUI `server.py` 的 `create_origin_only_middleware` 对回环地址校验
`Host == Origin`，8189 ≠ 8188 → 403。

**修复**：

- `app/proxy/passthrough.py`：抽出公共函数 `upstream_headers(request)`，
  剥离逐跳头 + Origin/Referer 改写为上游 authority；`forward_request` 改为复用。
- `app/proxy/prompt_submit.py`：`_forward_raw` 改用 `upstream_headers`。
- 新增 `tests/unit/test_passthrough_origin_headers.py`：2 项断言改写与剥离。

**验证**：`pytest tests/unit/test_passthrough_origin_headers.py tests/unit/test_privacy_confirm.py -q`
→ 17 passed。

**防回归**：透传头改写逻辑此后只有一处实现（`upstream_headers`），新增转发路径
一律复用，避免再出现双份逻辑漂移。
