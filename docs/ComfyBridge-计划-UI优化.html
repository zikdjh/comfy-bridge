ComfyBridge UI 界面优化计划

创建日期：2026-10-19 ｜ 版本：v0.1（筹备稿）｜ 状态：待启动

本文档在 UI 优化动手前完成现状盘点与方向规划，作为后续分批实施的依据。前期性能优化（代码分割、轮询治理、懒加载）已落地，本计划聚焦视觉一致性、信息层级、交互体验与移动端适配。

一、现状盘点

1.1 技术栈与约束

  • React 18 + Ant Design 5.19 + TanStack Query 5，构建 Vite 5（路由级代码分割已就绪）。
  • 全局主题：theme.ts 的 bridgeTheme，主色 #4f5be8，圆角 8，字号 13，菜单项高 38。
  • 设计语言基线：运营管理工具风格 —— 安静、克制、以扫读与反复操作为先，避免营销式视觉。
  • 现有 e2e 基线：web-perf-nav.spec.ts 采集 11 页导航 p50/p95（预算 300ms），UI 改动须保证基线不回退。

二、优化方向

2.1 建立设计 token 层（方向 A）

把颜色、间距、字号收敛到 theme.ts 与一组 CSS 变量 / AntD token，消灭 JSX 内魔法值：

  • 语义色板：primary / success / warning / danger / text-primary / text-secondary / border / surface。
  • 间距阶梯：4 / 8 / 12 / 16 / 24，替换散落的具体像素。
  • 为后续暗色模式预留 token 切换能力（本次只做 token 化，不强制做暗色）。

2.2 版面与信息层级收敛（方向 B）

  • 页面级容器改为无框布局（band + 受限内宽），Card 仅保留给真正的重复条目与弹层内容。
  • 仪表盘重构：统计区 / 图表区 / 实时请求区按「分区带」组织，去掉层层嵌套的 Card。
  • 页面标题行统一：标题 + 副标题/操作区，形成可扫读的页首。

2.3 组件归并与交互统一（方向 C）

  • 提炼 PageHeader、StatCard、StatusTag 等公共组件，替换多页重复片段。
  • 长任务操作封装统一反馈（按钮 loading、结果 message、失败重试入口一致）。
  • 表格体验统一：列宽策略、空状态引导（EmptyGuide 已有雏形）、横向滚动兜底。

2.4 移动端与响应式（方向 D）

  • Sider 在窄屏（<768px）自动收起为抽屉，Header 元素换行收纳。
  • 表格统一 scroll={{ x: true }} 策略，关键页验证窄屏可用。

三、建议批次与验收

批次内容验收方式
第 1 批方向 A（token 化）+ 方向 B 的仪表盘重构tsc 通过；web-perf-nav 基线不回退；桌面/窄屏截图对比
第 2 批方向 B 其余页面 + 方向 C（公共组件归并）全量 e2e 点击用例通过；逐页目检
第 3 批方向 D（响应式）+ 方向 C 收尾（反馈模式统一）窄屏冒烟用例 + 现有测试套件回归

每批独立提交，提交信息使用中文 conventional commits；改动遵循「运营管理工具」气质，不引入装饰性视觉。

四、动手前待确认

  • 暗色模式是否进入本次范围（默认不进，仅预留 token）。
  • 移动端支持目标：仅保证可用，还是做专门的信息重排。
  • 仪表盘三个分区（统计 / 趋势 / 实时请求）的默认展开顺序与主次权重。
