1 项目概述

项目名称
ComfyBridge —— 本地 ComfyUI 与 Modal 云端 GPU 之间的桥接器
一句话定义
本地常驻服务：把本地 ComfyUI 的生成请求按策略转发到 Modal 云端 GPU 执行，并对两端节点/配置/工作流做同步管理、统一记录日志与成本
技术栈
FastAPI（含 ASGI 反代 + WebSocket 中继）+ React（管理控制台）+ Modal Python SDK（云端 Runner 与数据卷）
项目性质
个人工具型项目，单人开发，服务自己的日常出图工作流
总体周期
8 个工作周 + 1 周缓冲，建议 2026-09-28 启动，2026-11-27 前完成（缓冲至 12-04）
总工作量
约 40 人日
配套文档
技术设计见《ComfyUI-Modal桥接器项目规划》；参考资料见《ComfyUI 启动参数参考》《Modal 云平台与 SDK 参考》

立项背景

  • 本地显卡无法胜任大模型/高分辨率/批量出图；Modal 提供按秒计费的 L40S～B200 GPU，无闲置成本。
  • 直接把 ComfyUI 搬上 Modal 后，本地前端习惯、工作流与素材被割裂；两端环境（节点、版本、路径）会持续漂移。
  • 已有一份可用的 Modal 部署脚本（comfyui_app.py），Runner 与数据卷基础已具备，缺的是中间的桥接层。

2 目标与成功标准

2.1 项目目标

  • G1 无感切换：用户仍用熟悉的 ComfyUI 界面出图，单次生成可留在本地或送上云端，切换零学习成本。
  • G2 环境一致：两端节点、ComfyUI 版本、设置、工作流可一键对齐，漂移可发现、可修复。
  • G3 可控上云：云端每次执行可追溯（决策链路、时间线、输出、成本），费用有预算护栏。
  • G4 模型不自动同步：模型仅存于本地与 Modal 数据卷两处，由用户通过管理界面对卷按需供给。

2.2 量化成功标准（KPI）

指标目标值
混合后端连续使用一个工作日，生成请求失败率（桥接层自身原因）0
本地新装 3 个自定义节点 → 云端可用（同步 + 镜像重建完成）≤ 10 分钟
请求日志可还原率（决策 + 时间线 + 输出 + 成本估算）100%
月度预算护栏生效（超限自动回落本地并通知）有效触发 ≥ 1 次验证
全新机器从安装桥接器到云端首图≤ 30 分钟
核心链路 e2e 通过率100%（冒烟集全绿）

9 质量管理

  • 分层测试：单元（路由求值/锁文件/合并/成本）→ 集成（mock 两端 ComfyUI 的全端点行为矩阵 + 同步冲突用例）→ live 联调冒烟（文生图/图生图/独占节点/中断/断网重连）→ e2e（Playwright）→ 兼容矩阵（远端 2 个版本）。
  • 代码门禁：ruff + mypy 通过、单测通过方可合并；主干保持可运行。
  • 设计红线：所有对 ComfyUI 协议的假设集中封装在兼容层（proxy 模块），禁止散落；prompt_id、二进制预览帧、status 广播三类场景必须有专项用例。
  • 安全基线：桥接器仅绑 127.0.0.1；Runner 端点必须带 Token 鉴权；日志中的图快照仅本地存储；预算护栏默认开启。
