ComfyBridge 性能优化执行计划

基线采集 · 启动提速 · 交互治理 · 云端受理 · 资源稳定

基线版本：v0.1.0-beta.7 · 编写日期：2026-10-21 · 配套《性能优化路线图》

1 背景与目标

性能工作已经有第一批成果：路由级拆包、页面轮询可见性治理、请求缓存和 Modal 自检缓存都已落地。下一阶段的目标是把剩余热点收敛，并把性能验证固化成门禁，避免“感觉变快”。

  • 启动：双击到可交互有稳定基线，冷热启动分开统计。
  • 交互：主页面切换预算统一，长列表不再出现渲染尖刺。
  • 受理：云端提交 p95 继续守住，受理与执行等待分开度量。
  • 资源：空闲 CPU / RSS / 句柄 / 端口不随时间增长。
  • 门禁：关键性能指标进测试，不只停留在文档。

4 执行批次

4.1 S1 · 基线固化

  1. 新增桌面启动采样：进程、runtime 检查、后端 spawn、端口 ready、窗口可交互。
  2. 新增页面切换与长任务采样，输出统一 JSON 报告。
  3. 把 P-06、P-08、启动、资源四类指标接入门禁。

4.2 S2 · 启动与首屏

  1. 并行化 runtime 检查与后端启动。
  2. 窗口先显示骨架，后端 ready 后恢复页面。
  3. 关键 chunk 预取，失败路径立即弹窗。

4.3 S3 · 交互渲染

  1. 日志页试点虚拟滚动，再扩展到媒体库和模型卷。
  2. 复杂表格做列级 memo 与筛选态缓存。
  3. 统一请求去重与 staleTime 策略。

4.4 S4 · 云端受理

  1. 受理链路分段打点。
  2. 节点与模型在场结果缓存，写操作按事件失效。
  3. 审计与图快照异步化，关闭前强制 flush。

4.5 S5 · 资源稳定

  1. 空闲轮询继续降频。
  2. 连接池生命周期统一治理。
  3. 长运行采样纳入发布前检查。

4.6 本轮 · 数据卷读取收敛

  • 请求合并：同一卷、同一目录在缓存未命中时只发起一次 VolumeListFiles，所有并发读者共享结果。
  • 并发上限：不同目录的读取统一经过进程内 4 路闸门，保留原有 TTL、退避重试与错误分类。
  • 正确性：写操作按目录边界失效缓存并取消受影响的在途读取；旧请求即使晚到也不能写回陈旧快照。
  • 取消隔离：单个 HTTP 读者取消不会中断仍有其他消费者的共享读取。
  • 覆盖：单飞复用、并发峰值、TTL 命中、写失效防回填、失败不缓存、等待者取消隔离均有单元回归。

6 风险与边界

  • 不牺牲正确性：缓存必须有 TTL、失效事件和手动刷新。
  • 不做假异步：异步日志和审计必须可落盘、可恢复。
  • 不引入重依赖：优先利用现有 React、FastAPI、SQLite 能力。
  • 不用绝对值一刀切：CI 和本机基线分开比较。
