1. 测试目标与强制规则

功能完整性逐项验证 11 个业务页面、404 页、公共 Shell、弹窗、抽屉、表格、筛选、表单与跨页跳转。
接口正确性覆盖 OpenAPI 中全部 89 个管理操作，并核对响应、持久化、任务副作用和前端联动。
数据面兼容性覆盖 ComfyUI 根页面、提示词提交、队列、节点清单、WS、历史、图片、上传与透明透传。
真机主链路通过 Web 出图界面提交真实任务，确认请求最终在 Modal 执行并回传产物。
异常可恢复覆盖 401/403、断线、超时、空数据、路径越界、任务取消、重试与预算拦截。
可审计每个用例留下实际结果、证据位置和执行状态，失败项能独立复现。
生图硬约束：所有真实生成请求必须显式设置 x-bridge-backend: modal，并在请求记录中确认 final_backend=modal。不执行本地文生图、图生图或视频推理。页面中任何可能落到本地的默认路由，只做“干跑预览”或拒绝路径验证。
  • 只启动 Web 前后端、本地 ComfyUI 与 Modal Runner；不安装、不运行桌面整合包。
  • Web 管理台操作使用 15173；管理 API 直连 18189/api/v1，同时抽样验证 Vite 的 15173/api/v1 代理。
  • 桥接数据面和出图界面使用 18189；本地 ComfyUI 8188 只作为上游依赖与状态观测点。
  • 测试数据统一使用 fulltest-20261018 前缀；写操作必须记录前值、后值并恢复。
  • 测试顺序从只读、低风险写入，到高成本 Modal 操作，最后执行破坏性与异常用例。
  • 任一 P0 失败立即停止高成本链路；修复并复测后再继续。
