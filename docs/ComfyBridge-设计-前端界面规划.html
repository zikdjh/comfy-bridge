1 规划原则

  • 控制台只做"运维"，不做出图：生成仍用原版 ComfyUI 界面（经桥接器 :8189 代理）。本控制台是路由、同步、模型、日志的驾驶舱，两者通过顶栏"前往出图界面"互通——避免把控制台做成第二个 ComfyUI。
  • 表格优先、信息密度高：用户是开发者本人，AntD 5 密集表格 + 抽屉详情，不做营销式大卡片。
  • 一切异步操作任务化：同步/重建/上传/导入统一走 sync_jobs + SSE，前端用统一的 JobDrawer 展示进度与日志，不出现"无反馈等待"。
  • 后端标签贯穿全局：本地 / 云端 两种 Tag 色在所有页面保持一致（本地=绿、云端=蓝紫），扫一眼即知执行位置。
  • 实时但可降级：SSE 实时刷新是增强，不是依赖；断线时页面仍可手动刷新查询（列表页均直接 GET）。
  • 桌面优先：本机工具，≥1280px 设计基准；侧栏可折叠以兼容小屏，不做移动端适配。

2.1 侧栏（可折叠）

  • 导航 7 项与路由一一对应；当前项高亮；每项带未处理数徽标（如：节点管理=待同步节点数、工作流=冲突数）。
  • 底部固定：版本号 + SSE 连接状态点（绿=已连接 / 灰=断线，悬停显示重连倒计时）。

2.2 顶栏

  • 后端状态胶囊（所有页面可见）：● 本地（版本 + 延迟）/ ● Modal Runner（状态：空闲/运行 N/冷启动中/离线）。数据源 GET /api/health + SSE backend.status，10s 轮询兜底。
  • 前往出图界面：新开标签页打开 /（即被代理的 ComfyUI 原版界面）。
  • 预算徽标：本月已用/上限，>80% 变橙色、超限变红色。

2.3 设计规范

项约定

语义色本地=green / 云端=geekblue / 冲突=orange / 错误=red / 同步完成=green；成功标准："任何页面截一张图，不用看文字就能分清本地与云端"

破坏性操作删除模型 / 回滚镜像 / 停止应用 → Popconfirm 二次确认，危险按钮红色

3.2 路由规则 M1

┌ 规则列表（上下拖拽=优先级）──────────────┐ ┌ 干跑预览器 ────────────────────┐
│ 1  manual         手动选择      → 按所选 │ │ [选择工作流 ▼] [粘贴JSON] [干跑]│
│ 2  tag            cloud:*       → 云端 ✓│ │ ① manual      跳过：未指定     │
│ 3  node_presence  本地缺失节点  → 云端 ✓│ │ ② tag         命中 cloud:*     │
│ 4  model_presence 卷内缺失模型  → 本地  │ │ ③ node_presence 跳过：规则未及  │
│ 5  default        兜底          → 本地  │ │ ⇒ 最终决策：云端（tag 规则命中）│
│                     [+ 新增规则]        │ │ [应用为规则建议]（P2）          │
└─────────────────────────────────────────┘ └────────────────────────────────┘
  • 规则行：序号、类型 badge、条件摘要（自动生成人话，如"包含本地缺失节点"）、目标后端 Tag、启用 Switch、编辑/删除。
  • 编辑抽屉 = 条件构建器：按类型切表单——tag（前缀输入）、node_presence（从差异缓存多选节点包/class_type）、model_presence（多选模型分类+文件）、size（分辨率阈值/视频节点开关）。
  • 干跑结果逐条列出命中/跳过与原因（来自 POST /api/routing/preview 的 rule_trace）；支持从日志页"以该请求重新干跑"进入。

3.3 节点管理 M2

区块设计
版本横幅顶部常驻：本地 v0.37.2 / 云端 vX；不一致 → 黄色 Alert + [对齐云端版本]；检测到 Desktop 自动更新过本地 → 提示"本地已更新，建议同步远端"
差异矩阵主表格：节点包名、版本/commit（短哈希）、本地状态、云端状态（✓ / ✗ / 构建 中）、依赖数、操作。筛选：仅本地有 / 仅云端有 / 全部；搜索框；视图切换：按节点包 ⇄ 按 class_type
批量同步勾选多行 → [安装到云端] → 模式选择弹窗：镜像固化（默认，说明"需重建镜像，约几分钟"）/ 卷试装（说明"免重建，冷启动变慢"）
JobDrawer同步任务抽屉：步骤条（生成锁文件→构建脚本→镜像重建→健康检查）+ 实时日志滚动 + 失败时红色回滚提示与 [查看上一版]

数据依赖：GET /api/nodes/diff、POST /api/nodes/sync、GET /api/jobs/{id}（SSE 推送进度）。

3.4 工作流 M2

区块设计
同步状态总表名称、本地（mtime/hash）、云端（mtime/hash）、状态 badge：已同步绿 / 仅本地 / 仅云端 / 有差异橙 / 冲突红、最近运行（后端 + 时间 + 次数）。行操作：→云 / ←本地 同步、对比、冲突处理
冲突处理弹窗左右双列：mtime / 大小 / hash / 内容摘要；三个动作：保留本地版本 / 保留云端版本 / 双副本保留（说明会生成 name.conflict-时间戳.json）。不提供自动合并（工作流 JSON 结构合并风险高）
运行统计 Tab按工作流聚合：运行次数、平均/最大耗时、估算成本、常用后端；点击钻取到日志页预过滤

3.5 模型卷 M3

区块设计
顶部统计条卷容量进度条（已用/总量）、分类数、本月新增/删除数
分类 Tabcheckpoints / loras / vae / controlnet / …（27 类，横向滚动 Tabs）：文件名、大小、mtime、引用次数（近 30 天日志统计，悬停列出工作流）、本地对照（✓ 本地也有 / 仅云端）、操作：删除
上传面板拖拽区 + 队列列表：分块进度、断点续传标识（已传 x/y 块）、MD5 校验状态、失败重试；上传中可最小化为角标继续浏览

删除保护删除 → 引用检查结果弹窗（"近 30 天被 3 个工作流使用"）→ 确认后软删除 30 天，页面顶部出现可撤销条

数据依赖：GET /api/models?side=、POST /api/models/upload（分块）、POST /api/models/hf-import、DELETE /api/models/{id}。

5 数据流与状态管理

5.1 分层

服务端状态
TanStack Query：全部 GET（列表/详情/健康/成本），SSE 事件到达时按类型 invalidateQueries；写操作用 mutation + 成功后失效对应查询
实时状态
zustand：SSE 连接状态、运行中任务表、后端健康快照、上传队列——跨页面共享、低延迟更新
事件协议
SSE 事件四类：request.updated（请求状态/进度）、job.updated（同步任务）、cost.updated、backend.status；载荷只带 ID + 摘要，详情由前端按需 GET，避免重推送大对象
类型生成
P2：从 FastAPI /openapi.json 用 openapi-typescript 生成 src/types/api.d.ts，替代手写 DTO（M1 先手写、与后端 schemas 同名对齐）

5.2 关键交互约定

  • 列表页一律"先 GET 渲染，SSE 增量刷新"；SSE 断开显示灰点，不阻塞手动刷新。
  • 长任务（镜像重建/HF 导入/大文件上传）提交后立即返回 job_id → 自动打开 JobDrawer → 用户可离开页面，顶栏出现全局任务角标。
  • 所有"上云"类动作遵循预算护栏状态：on_exceed=fallback_local 生效时，云端相关按钮置灰并提示原因。
