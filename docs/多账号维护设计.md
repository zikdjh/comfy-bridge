# ComfyBridge 多账号维护设计

## 1. 背景与目标

用户后续可能持有多个 Modal 账号（个人号 / 团队号、额度分散等场景），桥接器需要在这些账号之间切换使用云端 GPU 通道。桥接器当前是**单实例单账号**设计：`[modal]` 配置段只承载一组凭据，所有下游（modal CLI 封装、Runner 执行通道、卷管理、设置/节点同步）都直接读取当前生效配置。

本文档定义在不推翻该架构的前提下，以**账号档案注册表 + 激活切换**实现多账号维护。

## 2. 硬约束

1. **1 个账号只绑定 1 份凭据**：每个账号档案仅保存一组账户 API token（`ak-…`/`as-…`）及配套的 Runner 代理鉴权 token 族（`wk-…`/`ws-…`）；token 轮换 = 覆盖写回原档案，不做多凭据并存。同一 workspace 的两份 token 登记为两个档案。
2. 单实例同一时刻只有一个**活跃账号**；不支持单实例内并发多账号执行。需要并行使用多个账号时走多实例硬隔离路径（§5.4）。
3. 密钥只落盘 `~/.comfybridge/config.toml`（或 `CB_CONFIG_DIR` 指定的配置目录），API 层永不回显明文（沿用现有脱敏回显契约）。

## 3. 现状盘点

### 3.1 凭据消费路径（均为调用时读取）

| 消费方 | 凭据 | 读取方式 |
|---|---|---|
| modal CLI 子进程（卷/应用/账单等） | `MODAL_TOKEN_ID`/`MODAL_TOKEN_SECRET` 环境变量 | 每次子进程调用注入（`modal_volume/client.py`），值取 `get_settings().modal` |
| Runner 执行通道（HTTP/WS） | `Modal-Key`/`Modal-Secret` 代理鉴权头 | 每请求构造（`runner/client.py:proxy_headers()`），值取 `get_settings().modal` |

两路都在调用时读当前配置，因此**切换账号不需要改动任何消费方**，只需保证配置热生效 + 相关缓存失效。

### 3.2 账号维度的配置项

`[modal]` 段中随账号变化的字段构成一个「账号档案」的最小集：

| 字段 | 说明 |
|---|---|
| `token_id` / `token_secret` | 账户 API token（1 账号 = 1 份） |
| `proxy_token_id` / `proxy_token_secret` | Runner 端点代理鉴权 token 族 |
| `environment` | Modal 环境（空 = 默认环境） |
| `volume` | 数据卷名（per-workspace 物理卷，同名也是不同卷） |
| `app_name` / `web_url` | Runner 应用名与固定 Web 端点（**per-workspace**，换账号必须换） |
| `task_timeout` / `extra_launch_args` | 执行参数（可随档案走，也可保持全局，本期随档案） |

### 3.3 切换账号时必须失效的进程内缓存

| 缓存 | 位置 | 处置 |
|---|---|---|
| 配置缓存 | `core/config.get_settings`（lru_cache） | `cache_clear()`（现有 config PUT 已做） |
| object_info 合并缓存 | `proxy/object_info` | `invalidate_merge_cache()`（现有 config PUT 已做） |
| Runner 部署状态 | `runner/client._state`（60s TTL） | 置零，强制下轮按新 `app_name` 重新探测 |
| 卷用量缓存 | `volume_mgr/usage._CACHE`（60s TTL） | 置零（`volume` 随账号变） |
| modal CLI 最近状态 | `modal_volume/client._LAST_FAILURE/_LAST_SUCCESS_MS` | 清空（状态展示归零） |

### 3.4 落盘状态的处置

| 状态 | 位置 | 处置 |
|---|---|---|
| 节点差异缓存 | `~/.comfybridge/nodes_diff_cache.json` | **切换时重置**（缓存的是「本地 vs 当前云端」，云端已随账号变化） |
| 设置同步 | 无持久缓存，按请求实时 diff 新卷 | 天然生效，无需处理 |
| 版本对齐历史 | `~/.comfybridge/version_align_history.jsonl` | 仅追加的历史记录，保留 |
| 日志/成本/任务库 | `backend/data/bridge.sqlite3` | 实例级单时间线，切账号不迁移不合并；在途云端任务是切换护栏依据（§4.3） |

### 3.5 已有的多实例隔离基础

- `CB_CONFIG_DIR` 环境变量可整体重定向配置目录（config.toml、audit.log、版本对齐历史、节点差异缓存等全部落这里），e2e 已在用。
- 每实例独立端口 + 独立 `CB_CONFIG_DIR` = 物理隔离的多账号并行方案，零代码即可用。
- **缺口**：日志库 `DATA_DIR` 固定在 `backend/data/bridge.sqlite3`，多实例会共享同一库。硬隔离并行前需把 `DATA_DIR` 迁到 `config_dir()` 下（P1）。

## 4. 方案：账号档案注册表 + 激活切换

### 4.1 配置形态

`[modal]` 段保持「当前活跃账号的生效视图」语义不变——所有下游零改动。新增 `[[modal.accounts]]` 数组作为档案注册表：

```toml
[[modal.accounts]]
name = "personal"
token_id = "ak-..."
token_secret = "as-..."
environment = ""
proxy_token_id = "wk-..."
proxy_token_secret = "ws-..."
volume = "comfyui-data"
app_name = "comfyui-l40s"
web_url = "https://xxx.modal.run"
task_timeout = 3600
extra_launch_args = []
```

- **激活** = 把档案字段整体复制进 `[modal]` 生效视图（原子写 toml + §3.3 全量缓存失效）。
- **保存当前配置为档案** = 把 `[modal]` 当前值写回对应档案（「保存当前」按钮）。
- **token 轮换** = 覆盖写对应档案的 token 字段（1:1 约束的落地形式）。
- **唯一性校验**：`name` 唯一；`token_id` 唯一（同一 token 不允许登记为两个档案）。

### 4.2 API 设计

| 方法与路径 | 语义 |
|---|---|
| `GET /api/v1/config/accounts` | 档案列表（密钥脱敏，标记当前激活项） |
| `PUT /api/v1/config/accounts` | 新增或覆盖档案（body 含 `name`；触发唯一性校验） |
| `DELETE /api/v1/config/accounts/{name}` | 删除档案（活跃中的档案不允许删） |
| `POST /api/v1/config/accounts/{name}/activate` | 激活切换；在途云端任务 > 0 时 409 拒绝，`{"force": true}` 可越过 |

激活成功响应返回新配置视图；前端随后自动重探通道状态。

### 4.3 激活切换的完整流程

1. **在途护栏**：`logs/store.count_active_modal() > 0` → 409（除非 `force=true`）。切账号会让在途云端任务的结果采集落到旧 token 上，必须先让任务收尾或显式强制。
2. 档案字段复制进 `[modal]`。
3. 写回 config.toml（沿用 `_dump_toml`）。
4. 缓存失效（§3.3 全表）+ `nodes_diff_cache` 重置。
5. audit 记一条账号切换事件。

失败语义：toml 写入失败 = 配置未变 + 缓存未清，状态保持一致（写入中途失败的半写风险与现有 config PUT 相同，P1 改临时文件 + 原子替换）。

### 4.4 前端

设置页「Modal」卡片内新增「账号档案」区块：档案列表（名称 + 脱敏 token + 当前激活标记）、保存当前配置为档案、激活、删除（活跃项禁用删除）。激活后通道状态、卷用量、节点差异等由既有轮询自动刷新，无额外轮询通道。

## 5. 存储与版本隔离

### 5.1 存储：云端卷随 workspace 天然隔离

Modal token 绑定 workspace，同名卷在不同账号下是**不同物理卷**，隔离由平台保证。桥接器侧要做的只有两件：

1. `volume` 字段随账号档案走（档案含该字段，激活时整体切换）；
2. 切换后卷用量缓存失效（§3.3）。

本地 `input/`/`output/` 目录属于本地 ComfyUI，与账号无关，不隔离。

### 5.2 版本：lock 是桥接器仓库资产，跨账号一致

`modal-runner/lock/`（`comfyui_version.txt` + `nodes.lock.yaml`）决定云端装什么版本，所有账号的 runner 按同一份 lock 部署——两端版本一致性天然成立，且**有意不做** per-账号版本组合（差异化需求若出现，未来扩展 per-profile lock，明确非本期范围）。

### 5.3 部署联动

Runner App 部署在 workspace 内，`web_url` 是 per-workspace 端点。切到新账号后：

- 档案里已存 `web_url` → 直接生效；
- 档案从未部署过 runner → 通道状态显示「未部署」，由用户执行 `modal deploy modal-runner/runner.py`（一键部署列入 P1）。

### 5.4 多实例硬隔离路径

并行使用多账号：每实例独立端口 + 独立 `CB_CONFIG_DIR`（+ P1 完成 `DATA_DIR` 迁移后即完全隔离）。进程内档案切换适合「串行换号」，多实例适合「同时在线」，两者互补不互斥。

## 6. 阶段划分

### P0（本期，已落地）

1. `[[modal.accounts]]` 档案模型 + 解析/写回 + 唯一性校验（1:1 token）。
2. accounts CRUD + activate API（在途护栏、缓存失效、audit、脱敏）。
3. `nodes_diff_cache` 切换重置；runner / volume usage / modal CLI 状态缓存失效。
4. 前端设置页账号档案区块。
5. 单测：档案 CRUD、唯一性、激活联动（缓存清空 + 配置复制）、护栏 409、脱敏回显。

落地记录（2026-10-12）：

- 模型与写回：`backend/app/core/config.py`（`AccountProfile` + `ModalConfig.accounts`，TOML `[[modal.accounts]]` 往返）。
- API 与护栏：`backend/app/api/v1/config.py`（accounts CRUD + activate；在途任务 409 + force；`_invalidate_account_caches()` 联动五处缓存 + audit）。
- 缓存钩子：`runner/client.invalidate_state`、`volume_mgr/usage.invalidate_cache`（代际计数丢弃在途旧账号计算）、`modal_volume/client.reset_runtime_state`、`nodes_mgr/diff_cache.invalidate_all`。
- 前端：`api/config.ts`（accounts hooks）+ `pages/settings/AccountProfilesCard.tsx`（档案表、保存当前、激活二次确认、删除保护）。
- 单测：`backend/tests/unit/test_account_profiles.py`（16 例：CRUD/唯一性/激活联动/护栏/脱敏/TOML 兼容/钩子）。

### P1

- `DATA_DIR` 迁入 `config_dir()`（多实例硬隔离前提）。
- 成本/预算按账号分账（bridge.sqlite3 加账号维度或按档案分库；预算护栏读当前账号的月度额度）。
- runner 一键部署到新 workspace（`modal deploy` 后回填 `web_url`）。
- config.toml 原子写（tmp + replace）。

### P2+（暂缓）

- per-profile 节点 lock（差异化版本组合）。
- 审计页 / 日志页按账号筛选（依赖日志库账号维度）。

## 7. 测试计划

| 项 | 验证点 |
|---|---|
| 档案 CRUD | 新增 / 覆盖 / 删除；name 与 token_id 唯一性拒绝；活跃档案禁删 |
| 激活联动 | `[modal]` 字段整体替换；§3.3 缓存全部失效；nodes_diff_cache 重置 |
| 在途护栏 | `count_active_modal() > 0` 时 409；force 越过 |
| 脱敏 | 列表与响应中 token_secret / proxy_token_secret 永不出现明文 |
| 兼容 | 旧 config.toml（无 accounts 数组）加载不受影响 |
| e2e | CB_CONFIG_DIR 隔离实例上完成「保存档案 → 切换 → 通道重探」链路 |

## 8. 风险与开放问题

| 风险/问题 | 应对 |
|---|---|
| toml 写入中途失败留下半文件 | 与现有 config PUT 同风险；P1 改原子写，本期文档注明失败语义 |
| 切换后同名卷内容不同步（模型/设置） | 节点差异缓存已重置；模型清单与设置 diff 由既有页面重新拉取即可发现差异 |
| 同一 workspace 两份 token 建两个档案 | 允许（指向同一物理卷），符合「1 账号 = 1 份凭据」语义 |
| 激活期间后台任务（用量计算等）读旧配置 | 缓存置零后下轮重新计算；无长驻任务持有旧配置引用（get_settings 每次现读） |
